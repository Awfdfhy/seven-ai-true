# Settings UI System

Settings are grouped by user mental model, not runtime architecture. Use a small number of stable sections with clear headings; advanced/technical options remain inside an existing Advanced area if already supported. Mobile uses one-column flow; desktop may use grouped panels. A row contains label + optional helper + control. Destructive actions are isolated visually and require confirmation when irreversible. Status indicators use text/icon plus semantic color. No developer-dashboard styling for ordinary preferences.
