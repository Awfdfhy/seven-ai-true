# RPG_UI_SYSTEM — Seven RPG Experience

Priority: highest UI surface.

Seven RPG = AI conversation + narrative RPG + world simulation + character memory + canon + relationships + persistent state + player agency.

Therefore the UI is **story-first with contextual simulation tools**, not a traditional menu-driven RPG and not a recolored chat.

## Direction
Primary synthesis: **Modern AI × Fantasy + Cinematic Narrative + Living World Dashboard**.
Secondary accents: Royal Minimal and Ancient Codex for hierarchy/canon surfaces.
Avoid permanent HUD clutter, ornamental medieval chrome everywhere, tiny game-like stat text and modal spam.

## Story Stream
- Narrator blocks use a distinct narrative frame and chapter rhythm.
- Character speech is speaker-identified with optional portrait/avatar.
- Player actions remain visually simple.
- Choices appear only when an actual decision exists.

## Context surface
Phone: one contextual bottom sheet with Scene / Characters / World / Canon.
Wide screens: optional split-pane inspector.
It never permanently covers the story.

## Contextual Story HUD
Shows only meaningful state: location, chapter/scene, active objective, meaningful time/weather, danger/turn state. Auto-collapses when nothing important changed.

## Required RPG patterns
Character strip; character context on long-press/context action; subtle relationships; World State drawer; Canon timeline; Memory/Lore inspector; Scene summary; “Who knows what?” matrix; NPC relationship graph; faction/kingdom overview; branch history; decision consequence viewer with provenance; player-agency indicator; visually separate Narrator controls from Character controls.

## Mobile
Primary actions stay in the thumb zone. Deep state uses bottom sheets. Keyboard must never cover choices or composer. Persistent primary destinations should stay compact.

## Acceptance
RPG must be visually identifiable as a unique Seven mode from a screenshot with the logo hidden, while still sharing Seven tokens/components.
