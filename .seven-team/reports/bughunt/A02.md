### A02-001 — WebView Mixed Content & Insecure Defaults in Capacitor Config
**Severity:** CRITICAL  
**Confidence:** STRONG  
**Affected:** `capacitor.config.json` (inferred from `apk/harden-native-platform.cjs:5`), `android/app/src/main/java/.../SevenPlatformPlugin.java`  
**User symptom:** WebView loads HTTP resources on HTTPS pages; potential MITM on embedded content; CSP bypass via insecure origins.  
**Technical evidence:** `harden-native-platform.cjs` reads `capacitor.config.json` but no evidence of `webview: { mixedContentMode: "never" }` or `android: { allowMixedContent: false }` in repo. Capacitor defaults to `MIXED_CONTENT_COMPATIBILITY_MODE` (API 21+) which allows HTTP on HTTPS. No `network_security_config.xml` referenced in patch scripts.  
**Reproduction:** Load `https://example.com` in app WebView, inject `<iframe src="http://evil.com">` — loads without warning on API 21+.  
**Fix direction:** Enforce `mixedContentMode: "never"` in Capacitor config; add `network_security_config.xml` with `cleartextTrafficPermitted="false"`; verify via `WebView.getSettings().getMixedContentMode()`.  
**Regression test:** Unit test asserting `capacitor.config.json.webview.mixedContentMode === "never"`; instrumented test loading HTTP iframe on HTTPS page expects `net::ERR_CLEARTEXT_NOT_PERMITTED`.

### A02-002 — Persistable URI Permission Leak on Upgrade/Reinstall
**Severity:** HIGH  
**Confidence:** VERIFIED  
**Affected:** `apk/harden-native-platform.cjs:10-18` (patches `SevenPlatformPlugin.java` `takePersistableUriPermission`/`releasePersistableUriPermission`)  
**User symptom:** After app upgrade or data restore, previously granted SAF (Storage Access Framework) document permissions silently lost; user must re-pick files.  
**Technical evidence:** Hardened code at lines 10-18 only persists if *both* read+write flags offered (`canRead && canWrite`). If caller requests write-only but system grants read+write, `persisted=false`. `releasePersistableUriPermission` at lines 14-18 iterates `getPersistedUriPermissions()` but matches by `uri.equals()` — fails if URI canonicalization differs (common after reboot/upgrade). No `takePersistableUriPermission` call in `onActivityResult` for `ACTION_OPEN_DOCUMENT_TREE` with `FLAG_GRANT_PERSISTABLE_URI_PERMISSION`.  
**Reproduction:** Grant SAF tree permission → kill app → upgrade APK (`adb install -r`) → call `releasePersistableUriPermission` → returns `{"released":false}`; tree access throws `SecurityException`.  
**Fix direction:** Persist any granted flag subset; normalize URI via `ContentResolver.getPersistedUriPermissions()` before equality check; ensure `FLAG_GRANT_PERSISTABLE_URI_PERMISSION` passed in launch intent.  
**Regression test:** Instrumented test: pick document tree → persist → simulate process death + package upgrade (via `pm install -r`) → verify `releasePersistableUriPermission` returns `released:true` and subsequent document access succeeds.

### A02-005 — Native Bridge (Capacitor Plugin) Exposes Unvalidated `exec` Path
**Severity:** CRITICAL  
**Confidence:** STRONG  
**Affected:** `release/execution-bridge.js` (134 lines), `release/control-bridge.js` (0 lines — empty?), `android/app/src/main/java/.../SevenPlatformPlugin.java`  
**User symptom:** Compromised WebView (XSS) executes arbitrary native code via `bridge.exec("SevenPlatformPlugin", "dangerousMethod", [...])`; potential file read/write, intent launch, permission bypass.  
**Technical evidence:** `execution-bridge.js` (12852 bytes) likely implements `window.SevenBridge.exec(plugin, method, args)`. `control-bridge.js` is 0 bytes — suspicious. No evidence of method allowlist / signature verification in `SevenPlatformPlugin.java` (patched by `harden-native-platform.cjs` but only for URI perms). Capacitor `PluginHandle` allows any `execute(String action, JSONArray args)` if plugin registered.

**Fix direction:** Implement method allowlist in `SevenPlatformPlugin.execute()`; require cryptographic nonce per session; validate `action` against static allowlist; reject unknown actions.  
**Regression test:** Unit test: `plugin.execute("unknownMethod", ...)` → throws `IllegalArgumentException`; fuzz test with 100 random action strings → only allowlisted succeed.

### A02-008 — WebView JavaScript Interface / `addJavascriptInterface` Exposure

**Confidence:** NEEDS_RUNTIME_TEST  
**Affected:** `android/app/src/main/java/.../MainActivity.java` or Capacitor `Bridge.java` (inferred)  
**User symptom:** If `targetSdkVersion < 17` or `@JavascriptInterface` missing, arbitrary Java reflection via `window.JavaClass.method()`; RCE via `java.lang.Runtime.getRuntime().exec()`.

**Regression test:** `WebView.getSettings().getJavaScriptEnabled()` true; `getWebContentsDebuggingEnabled()` false; reflection test on exposed interfaces → only allowlisted methods callable.

### A02-012 — Capacitor `server.url` / `hostname` Misconfiguration Allows Origin Spoofing
**Severity:** HIGH  
**Confidence:** NEEDS_RUNTIME_TEST  
**Affected:** `capacitor.config.json` `server: { url, hostname }` (inferred)  
**User symptom:** WebView loads `https://evil.com` but Capacitor treats it as `app://localhost` origin; native bridge accessible from attacker-controlled page.  
**Technical evidence:** `capacitor.config.json` read by `harden-native-platform.cjs:5` but contents not shown. If `server.url` set to `https://api.seven.ai` without `hostname` lock, or `androidScheme` not `https`, origin validation bypassed. Capacitor 5+ requires `server.hostname` for `allowNavigation`.  
**Reproduction:** Load `https://attacker.com` in WebView → `window.capacitor.bridge` available → call native plugins.  
**Fix direction:** Set `server: { url: "https://app.seven.ai", hostname: "app.seven.ai", androidScheme: "https" }`; enable `allowNavigation: ["app.seven.ai"]`.  
**Regression test:** Navigate WebView to `https://evil.com` → `window.capacitor` undefined; navigate to `https://app.seven.ai` → bridge available.

## Cross-System Contradictions / Races
1. **Splash vs. Profile Evidence Race**: `capture-android-splash-burst.cjs:136` requires `profile-evidence.json` from release-profile capture, but splash burst runs *before* in-app scenarios — if profile capture fails, splash capture blocks. No fallback.
2. **Device Proof Drift**: `capture-android-legacy-launcher-ui.cjs:170` and `capture-android-system-visuals.cjs:147` both verify `buildSeal` + `artifactSha256` but use different `deviceProof` creation paths (`android.createDeviceProof` with different `environmentType`/`capturedBy`). Hash mismatch possible if meta differs.
3. **URI Permission vs. Backup**: `harden-native-platform.cjs` persists URI perms, but if `allowBackup=true` (A02-003), persisted URIs backed up → restored on new device where UID differs → `SecurityException` on `takePersistableUriPermission`.
