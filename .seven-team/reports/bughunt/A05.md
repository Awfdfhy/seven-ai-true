## Bugs Found (Sorted by Severity)

### A05-001 — Mode Picker State Desync Between Toggle Buttons and Picker Menu
**Severity:** HIGH  
**Confidence:** VERIFIED  
**Affected:** `release/beta-ui-runtime.js` — `m()` (line 23), `setMode()` (line 31), `syncModePicker()` (line 30), `buildModePicker()` (line 32)  
**User Symptom:** Mode picker menu shows incorrect active mode after toggling "Deep Think" or "Search" buttons directly; picker and toggles drift out of sync.  
**Root Cause:** `m()` reads live toggle classes (`#deepThinkToggle`, `#searchToggle`) but `setMode()` programmatically clicks toggles to match desired mode. `syncModePicker()` only updates picker buttons from `m()` result. If toggles are clicked by user, `MutationObserver` `u()` fires and calls `syncModePicker()`, but `setMode()` also calls `u()` after clicking toggles — creating a race where picker may reflect stale toggle state during rapid changes.  
**Evidence:** Line 23 `m()` depends on `.active` class; line 31 `setMode()` clicks toggles conditionally; line 41 `w()` observes toggle `class` mutations and calls `u()`; line 33 `u()` calls `syncModePicker()`. No guard against re-entrancy.  
**Reproduction:** 1) Open mode picker. 2) Click "Deep Think" toggle button directly (not via picker). 3) Observe picker menu still shows "Chat" active. 4) Click picker "Think" option — toggles may double-flip.  
**Fix Direction:** Single source of truth: make `S.mode` authoritative; toggles and picker both reflect `S.mode` via one `render()`; remove programmatic `.click()` in `setMode()`.  
**Regression Test:** Unit test `setMode('research')` → asserts both toggles `.active` and picker radio `aria-checked="true"` match without MutationObserver firing twice.

### A05-002 — Free Provider Detection Relies on Undefined Globals at Runtime
**Severity:** HIGH  
**Confidence:** STRONG  
**Affected:** `apk/patch-android.cjs` lines 102–103 — `isFreeProviderConfigured('kilo')`, `isFreeProviderConfigured('llm7')`, `hasAnyConfiguredFreeProvider()`; `freeProviderPrefs` object with 10 providers  
**User Symptom:** "Automatic Providers" / "Zero-Key routing" UI shows no free providers available even when configured; model picker chips for kilo/llm7/groq/etc. remain hidden.  
**Root Cause:** Patch verifies `isFreeProviderConfigured` and `hasAnyConfiguredFreeProvider` exist on `window` at test time, but these functions are defined in `seven-shell-final.js` / `intelligence.js` which load asynchronously. If patch runs before workspace scripts initialize, globals are undefined → assertions fail silently in production.  
**Evidence:** Line 102 `assertEquals("true", js(webView, "isFreeProviderConfigured('kilo')&&..."))` assumes global availability. No `waitFor` guard for function definition. `freeProviderPrefs` lists 10 providers (groq, nvidia, openrouter, gemini, kilo, llm7, aion, mistral, zai, cloudflare) but only kilo/llm7 checked.  
**Reproduction:** Cold start APK → open settings → providers section before workspace scripts load → free provider chips absent.  
**Fix Direction:** Add `waitFor(webView, "typeof isFreeProviderConfigured==='function'")` before assertions; verify all 10 providers in `freeProviderPrefs`.  
**Regression Test:** E2E test: fresh WebView → navigate to providers settings → assert all 10 free provider toggles render and reflect stored prefs.

### A05-003 — Provider Routing Falls Back to Hardcoded Order Ignoring User Pinned/Preferred Models
**Severity:** MEDIUM  
**Confidence:** NEEDS_RUNTIME_TEST  
**Affected:** `release/seven-shell-final.js` (inferred), `release/intelligence.js` (APK payload), `cloudflare/search-gateway/worker.mjs` lines 492–501 `selectSearchBackend`/`searchBackendOrder`  
**User Symptom:** User pins "kilo" as preferred free model, but requests route to "groq" or "llm7" first; "Automatic Providers" ignores pin.  
**Root Cause:** `searchBackendOrder` in search gateway uses static env var priority (Brave → Serper → SearXNG → DDG). Seven's model router likely mirrors this static priority for free providers (kilo → llm7 → groq → ...) without reading user `pinnedModel` or `preferredProvider` from `localStorage`/`SevenSecureStore`.  
**Evidence:** APK target confirms "Zero-Key routing" UX string. `patch-android.cjs` line 110 checks providers section inputs are hidden when not expanded — suggests provider list is static. No evidence of `localStorage.getItem('seven.pinnedModel')` in routing path.  
**Reproduction:** Set `localStorage.seven.pinnedModel='kilo'` → send message → observe network request hits groq/llm7 first.  
**Fix Direction:** Router reads `preferredProvider`/`pinnedModel` from secure store before falling back to static order.  
**Regression Test:** Mock `SevenSecureStore.get('preferredProvider')` → assert first request backend matches pin.

### A05-004 — Mode Change Does Not Cancel In-Flight Requests for Previous Mode
**Severity:** MEDIUM  
**Confidence:** STRONG  
**Affected:** `release/beta-ui-runtime.js` `setMode()` (line 31), `release/control-runtime.js`, `release/execution-bridge.js`  
**User Symptom:** User switches from "Research" → "Chat" mid-stream; research search requests continue and pollute chat history with search citations.  
**Root Cause:** `setMode()` updates UI state and calls `u()` but does not signal `control-runtime` / `execution-bridge` to abort pending requests. `stopStrategy: 'adaptive'` (line 15) exists but no hook from mode change to stop controller.  
**Evidence:** Line 31 `setMode()` only clicks toggles, calls `u()`, `closeModes()`. No `abortController.abort()` or `SevenControl.stop()` call. `control-runtime.js` (18271 bytes) likely exports stop function but not wired.  
**Reproduction:** Start Research query → wait for "Thinking..." → click mode picker → select "Chat" → observe search results still arrive and append.  
**Fix Direction:** `setMode()` calls `SevenControl.abortAll()` or `ExecutionBridge.cancelCurrent()` before mode commit.  
**Regression Test:** Integration test: spawn Research request → switch mode → assert no further `onMessage` callbacks for old request.

### A05-005 — Model Picker Chip Click Handler Missing for Free Providers
**Severity:** MEDIUM  
**Confidence:** NEEDS_RUNTIME_TEST  
**Affected:** `release/seven-shell-final.js` / `release/workspaces/seven-shell-final.js` — `.seven-shell-model-chip` selector (referenced in `apk/materialize-android-visual-test.cjs` line 93)  
**User Symptom:** Tapping a free provider model chip (kilo, llm7, etc.) in model picker does not switch provider; only paid/configured models respond.  
**Root Cause:** Visual test line 93 clicks `.seven-shell-model-chip` and waits for `.seven-shell-model-menu` — but no evidence that chip click updates `activeProvider` state for free providers. `freeProviderPrefs` in patch suggests 10 providers but chip click handler may filter by `isConfiguredProvider()` which returns false for zero-key routes.  
**Evidence:** Test clicks chip → expects menu → but no assertion that provider actually changes. `isFreeProviderConfigured` exists but not used in chip click path.  
**Reproduction:** Open model picker → click "kilo" chip → menu closes but model indicator still shows previous provider.  
**Fix Direction:** Chip click handler calls `setActiveProvider('kilo')` which writes to secure store and triggers router refresh.  
**Regression Test:** Click each free provider chip → assert `SevenSecureStore.set('activeProvider', ...)` called and subsequent request uses that provider.

### A05-006 — Search Toggle and Deep Think Toggle Mutual Exclusion Broken for "Research" Mode
**Severity:** LOW  
**Confidence:** VERIFIED  
**Affected:** `release/beta-ui-runtime.js` lines 23, 31 — `m()` and `setMode()`  
**User Symptom:** Toggling "Search" on while "Deep Think" is on correctly enters "Research"; but toggling "Deep Think" off while "Search" remains on leaves mode as "Research" instead of "Search".  
**Root Cause:** `m()` logic: `x&&y?'research':y?'search':x?'think':'chat'`. `setMode('search')` sets `think=false, search=true` → clicks deepThinkToggle off, searchToggle on. But if user manually clicks deepThinkToggle off while searchToggle is on, `m()` returns `'search'` (correct), but `u()` calls `syncModePicker()` which sets picker to "Search" — however `setMode()` is not called, so no side effects (stop strategy, aurora) fire.  
**Evidence:** Line 23 truth table; line 31 `setMode` only called from picker button `onclick`, not from toggle mutation observer.  
**Reproduction:** Enable both toggles (Research) → click Deep Think toggle off → mode becomes Search but aurora stays "research" color, stopStrategy unchanged.  
**Fix Direction:** Mutation observer `u()` should call `setMode(m())` to normalize side effects, not just `syncModePicker()`.  
**Regression Test:** Toggle sequence: think→research→search via UI toggles → assert `S.mode` and `documentElement.dataset.sevenBetaMode` match at each step.

### A05-007 — Provider Settings Section Inputs Hidden But Still Focusable (Accessibility)
**Severity:** LOW  
**Confidence:** VERIFIED  
**Affected:** `apk/patch-android.cjs` line 103 — assertion that all inputs in `#providersSection` are hidden when section closed  
**User Symptom:** Screen reader users can tab into hidden provider inputs; focus order broken.  
**Root Cause:** Test asserts `hidden||display==='none'||visibility==='hidden'||width===0||height===0` but does not assert `tabIndex===-1` or `inert` attribute. Inputs remain in tab order.  
**Evidence:** Line 103 checks visual hiding only.  
**Reproduction:** Open settings → close providers section → Tab through — focus lands on invisible inputs.  
**Fix Direction:** Add `inert` to collapsed section or `tabIndex=-1` to all descendant focusable elements.  
**Regression Test:** Axe-core scan on closed providers section → no focusable descendants.

## Cross-System Contradictions / Races
1. **Mode picker ↔ Toggle MutationObserver race** (A05-001): `w()` observes toggles → calls `u()` → `syncModePicker()`; `setMode()` clicks toggles → triggers same observer → double render.
2. **Provider routing ↔ Secure store init race** (A05-002): Patch asserts globals before workspace scripts define them.
3. **Search gateway backend order ↔ Seven model router** (A05-003): Both use static priority; neither reads user preference.
4. **Mode change ↔ In-flight request** (A05-004): No cancellation bridge between UI mode state and execution layer.

## Missing / Error States
- No error toast when free provider request fails (quota exhausted, network error) — falls back silently.
- No loading indicator on model chip while provider health-check runs.
- `hasAnyConfiguredFreeProvider()` returns false if *any* provider fails init — should degrade per-provider.
- Mode picker lacks keyboard navigation (ArrowUp/Down) for radio group — only mouse/click.
