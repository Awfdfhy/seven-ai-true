## 2. Bugs found (by severity)

### B04-001 — CRITICAL · VERIFIED
**Surface:** `runDeepThink()` `seven_ai-final.html:4131-4139`
**Symptom:** With Deep Think (or Research, which force-enables it) enabled, every final answer can be rejected outright on OpenAI-compatible providers (OpenRouter, Gemini, Mistral, z.ai, Cloudflare), or the injected reasoning brief is silently dropped. User sees a raw `400 … must be at the beginning` / "system message must be first" error instead of an answer, or an answer that ignores Deep Think entirely.
**Root cause:** The reasoning brief is **appended as a trailing `system` message**:
```js
const finalMessages = messages.map(m => ({ ...m }));
finalMessages.push({ role: "system", content: "Use this compact internal decision brief…\n\n" + reasoning });
```
The same invariant is enforced as a project contract one screen above at `:6688` (`if (bundle.messages.length === 0 || bundle.messages[0].role !== "system") return false;`). `buildContext` returns messages whose `messages[0].role === "system"` (validated), then Deep Think appends a **second** system message at the **end**. Two distinct failures follow:
- Strict providers (OpenRouter/Gemini/ZAI/Mistral) reject a non-leading `system` message → hard 400 for the whole turn.
- Permissive providers drop the trailing system message → Deep Think is a no-op for the final pass, while the hidden pass still consumed a full billable round-trip.
Nothing re-validates `finalMessages` before `requestAI`.
**Repro:** Set model to any non-Groq free provider, enable Think, send "hi". Deterministic unit repro: build `finalMessages` from a valid bundle; assert `messages.filter(m=>m.role==='system').length === 1 && messages[0].role === 'system'` — fails today.
**Fix direction:** Merge the brief into the existing leading system message (concatenate into `messages[0].content`), or demote it to `role:"user"`/`"assistant"` framing. Re-run `validateContextBundle` on the post-Deep-Think array before `requestAI`.
**Regression test:** Post-`runDeepThink` invariant test — after the two-pass flow, assert exactly one `system` message and it is at index 0; add a strict-provider body-shaping test per provider branch.

### B04-002 — HIGH · VERIFIED
**Surface:** `generateReply()` :7931-7936 vs `activeDeepThinkPerformance` (module-global, :3999)
**Symptom:** Deep Think perf telemetry is attributed to the wrong room/request. `SevenDeepThinkPerformance.snapshot()` reports `roomId`, budgets and route of a *previous* conversation while a new one is still reasoning — misleading diagnostics, and `finishDeepThinkPerformanceV1` can clear state belonging to another in-flight request.
**Root cause:** `beginDeepThinkPerformanceV1(roomId)` is only called when `controllerPlan.deepThink.use` (:7931), but `runDeepThink` mutates the module-global `activeDeepThinkPerformance` whenever it is non-null (:4099-4102, :4129-4135) — with no room or run-id check. `generateReply` does guard UI with `if (currentRoom === roomId)` (:7932), so a room switch mid-request lets request A's `runDeepThink` continue writing into whatever `activeDeepThinkPerformance` request B installed. A single global also means two overlapping Deep Think requests (research gateway callback, regenerate, retry) share one slot.
**Repro:** Start Deep Think in room 1, switch room before the hidden pass returns, start Deep Think in room 2 → room 2's `runDeepThink` overwrites room 1's `hiddenBudget`/`deepRoute`.
**Fix direction:** Key telemetry by `executionRunId`/room in a Map, or clear/discard `activeDeepThinkPerformance` when `currentRoom !== roomId`.
**Regression test:** Interleaved-room test asserting each run's snapshot retains its own `roomId`/route.

### B04-003 — HIGH · VERIFIED
**Surface:** `deepThinkPolicyForRequest()` :4018-4037 + `getContextInputTokenBudget()` :6549-6560
**Symptom:** In Auto routing mode Deep Think (and normal chat) silently under-provisions context: history, knowledge, pinned notes and web evidence get truncated/omitted far earlier than the UI suggests, degrading answers for long conversations — with no visible warning.
**Root cause:** Two separate context-window estimates disagree.
- `getContextInputTokenBudget()` in auto mode takes `Math.max(...configured.map(m => m.contextWindow))` — the **largest** configured model window (up to 1,048,576 for NVIDIA/Gemini seeds), so it budgets for the best-case model.
- The actual routed model is chosen later by `analyzeModelRequestV3`/ranking (`modelContextHeadroomScoreV3` :3555, `buildModelRankingContextV3` :3568), which scores on `requiredContext = inputTokens + outputBudget + 2048` against **each** candidate and returns `-Infinity` when `windowSize < requiredContext`.
So `contextBudgetTokens` is computed for a 1M-window model but the request may be routed to a 131,072-token model. A budget sized at ~1,045,000 tokens is then compiled by `budgetContextProjection` and handed to a 131k model → provider 400 "context length exceeded", or Deep Think's `hiddenMaxTokens` compounding it.
**Repro:** Enable Auto routing with a Groq 131,072 model + NVIDIA 1,048,576 model both configured; start a long Deep Think request → budget ≈ 1.04M, actual route may be the 131k model.
**Fix direction:** Budget against the *selected* model's `contextWindow` (or the conservative `min` across eligible models), and re-derive budget after routing, not before.
**Regression test:** Assert `contextBudgetTokens <= modelLimits(routedModel).contextWindow - output - safety` for every routed model in auto mode.

### B04-004 — MEDIUM · VERIFIED
**Surface:** `DEEP_THINK_SPEED_POLICY.budgets` :3994-3998 vs `normalizeRequestConfig()` / `callGroq()` maxTokens handling
**Symptom:** Deep Think's hidden pass can be silently clamped far below the tier budget, so "high"/"veryHigh" reasoning often costs the same tokens as "low".
**Root cause:** `deepThinkPolicyForRequest` sets `hiddenMaxTokens = max(512, min(limits.maxTokens, requested))` using `modelLimits(model)` — the *selected* descriptor's `maxTokens`. But the final `requestAI` path re-derives limits from `normalizeRequestConfig`: `safeMaxTokens = Math.min(limits.maxTokens, max(1, safeMaxTokens))` where `limits` is `modelLimits(targetModel)` after `isValidFreeModelSelection` fallback to `currentModel`. Two different descriptor resolutions (`resolveFreeModelDescriptor` may return null → falls back to `DEFAULT_MODEL` at :1202-1203) can yield different ceilings, so the policy's computed budget and the transmitted `max_completion_tokens` diverge. Also `budgets.veryHigh = 9216` can exceed small-window models, where `min(limits.maxTokens,…)` reduces it silently with no telemetry (`hiddenBudget` records the pre-clamp policy value, not the transmitted one).
**Repro:** Compare `SevenDeepThinkPerformance.policy(...).hiddenMaxTokens` against the actual `max_completion_tokens` sent in `callGroq` for a model whose descriptor lookup hits the `DEFAULT_MODEL` fallback.
**Fix direction:** Record the post-clamp value in telemetry; resolve the descriptor once and pass the resolved `maxTokens` explicitly.
**Regression test:** Assert `snapshot.hiddenBudget === transmitted max_completion_tokens` for each tier × model.

### B04-005 — MEDIUM · VERIFIED
**Surface:** `toggleDeepThinkMode()` :2599-2602 vs `release/beta-ui-runtime.js` mode picker (:23, :31, :41)
**Symptom:** After using the release **mode picker** ("Research" mode), the Deep Think toggle state and the reasoning-mode label can desynchronize from the actual `deepThinkMode`/`researchMode` flags, so the UI shows one mode while the orchestrator plans another (e.g. picker says Chat but `researchMode` stays on, silently forcing Deep Think + web search for subsequent messages).
**Root cause:** `beta-ui-runtime.js` computes mode purely from DOM classes (`dx.classList.contains('active')`) and drives toggles by dispatching `.click()`; but the real flags are `deepThinkMode`/`searchMode`/`researchMode` (:1341-1343), mutated only by `toggleDeepThinkMode()`/`toggleSearchMode()`/`toggleResearchMode()` (:2599, :4244, :4249). Any toggle state that changes without going through those functions (init, room/provider reset, or a picker path that sets classes directly) leaves the class-derived picker mode and the flag-derived controller plan (`createCognitiveRequestPlan` :7336-7338) disagreeing. `researchMode` is never re-read by the picker at all.
**Repro:** In release build, open mode picker → choose Research → choose Chat; then check `deepThinkMode`/`researchMode` — the class view can say Chat while `researchMode===true`, so the next send still plans research + enhanced verification.
**Fix direction:** Make the flags the single source of truth and have the picker call the real toggle functions; re-sync flags on init/room switch.
**Regression test:** Picker/flag coherence test — after every mode transition, `modeFromFlags() === modeFromDom()`.

### B04-006 — MEDIUM · VERIFIED
**Surface:** `generateReply()` "Preparing context…" bubble :7932-7934 vs `catch` :8085-8115
**Symptom:** If the Deep Think path throws **before** the reasoning bubble is replaced (e.g. `buildContext` throws "Context compilation failed validation", memory/web step fails), the "Preparing context…" placeholder bubble can remain in the room, and in a non-current room the error `bubble` is never surfaced — the room is left with a stuck "Preparing context…" message and no explanation.
**Root cause:** The placeholder bubble is created via `addMessage("assistant","")` and mutated with raw `innerHTML`. The `catch` block only sets `bubble.textContent` for the error/stopped states, but `bubble` is only non-null when `controllerPlan.deepThink.use && currentRoom === roomId` (:7932). If the room changes or an earlier step throws, the placeholder in the original room persists. There is no cleanup that removes or finalizes the placeholder on the failure path.
**Repro:** Enable Think, force `compileContextBundle` to return null (invalid bundle) in room 1, switch to room 2 mid-flight → room 1 keeps a permanent "Preparing context…" bubble.
**Fix direction:** Always create the placeholder when `deepThink.use` (regardless of `currentRoom`), and clear/finalize it in a `finally`/error path.
**Regression test:** Inject a failure in `buildContext` for each plan step; assert no placeholder text persists in any room.

### B04-007 — LOW · VERIFIED
**Surface:** `#deepThinkToggle` HTML :843 + `toggleDeepThinkMode()` :2599
**Symptom:** The Think toggle exposes no accessible pressed state; screen readers cannot announce on/off, and the release audit records `aria-pressed` count = 0 across the file.
**Root cause:** The button toggles only the `active` class and has no `aria-pressed` attribute maintained in JS. The release `beta-ui-runtime.js` mode picker adds `role="radio"`/`aria-checked` for its own options, but the underlying toggle button itself has no accessible state.
**Repro:** Inspect `#deepThinkToggle` attributes before/after toggle — `aria-pressed` never appears.
**Fix direction:** Set `aria-pressed` (and keep `aria-label`) in `toggleDeepThinkMode()`.
**Regression test:** Assert `aria-pressed` flips true/false alongside the `active` class.

## 3. Cross-system contradictions / races

1. **System-message invariant contradiction (CRITICAL, = B04-001).** `validateContextBundle` (:6688) mandates `messages[0].role === 'system'`; `runDeepThink` (:4136) appends a *second, trailing* `system` message. The context layer's own contract is violated downstream with no re-validation. This is the most serious cross-system inconsistency found.
2. **Budget/routing disagreement (= B04-003).** `getContextInputTokenBudget` sizes context for the largest auto-mode window; the ranking layer routes per-candidate against each model's own window. Two subsystems compute incompatible context budgets for the same request.
3. **Telemetry global vs per-run (= B04-002).** Room-scoped requests write to a module-global `activeDeepThinkPerformance` with no room/run key; the orchestrator's `currentRoom === roomId` UI guard prevents visible breakage but not data corruption.
4. **Flag state vs DOM-class state (= B04-005).** Controller plan derives from JS flags; the release mode picker derives from CSS classes; research mode isn't represented in the picker's model at all.
5. **`isGenerating` single global (low risk, informational).** `generateReply` relies on one global `isGenerating` (:1344) for its only re-entrancy guard (:6327, :6368). Deep Think's long hidden pass lengthens the window where a stray dispatch could race. No second Deep Think can start, so this is a robustness note rather than a confirmed defect.

## 4. Missing / error states

- **No fallback when the hidden reasoning pass 400s.** `runDeepThink` lets the provider error propagate (:4117 await `requestAI`); the whole turn then fails, even though the context is already valid and a plain chat answer was possible. A "Deep Think unavailable, answering normally" degrade path is absent.
- **No post-Deep-Think message re-validation** (see B04-001): `validateContextBundle` is never invoked on `finalMessages`.
- **Non-string reasoning content hard-fails** (:4143) with a generic error; no single-pass fallback.
- **Telemetry `hiddenBudget` records the policy value, not the clamped transmitted value** (= B04-004), so under-provisioning is invisible in diagnostics.
- **Placeholder bubble has no failure terminal state** (= B04-006).
- `DEEP_THINK_SPEED_POLICY.version` is 2, but `SevenDeepThinkPerformance.version` is 1 and `beginDeepThinkPerformanceV1` stamps `version:1` — three mismatched version constants in one subsystem (cosmetic, but signals the policy evolved without a schema bump).

## 5. False positives rejected

- **B04-004b — "Gemini rejects trailing system":** initially suspected Gemini-specific ordering, but the app sends OpenAI-style `role` strings through a single shared `callFreeModelFabric`; there is no Gemini-specific branch that reorders messages, so the core issue is the app sending a non-leading `system` to OpenAI-compatible endpoints (folded into B04-001, not counted separately).
- **Deep Think double-billing as a separate bug:** the hidden pass plus final pass is documented two-pass behavior (`DEEP_THINK_SPEED_POLICY` / `runDeepThink` comment at :2604-2610), not a defect. Only the resulting broken message shape is a bug (B04-001).
- **`getReasoningEffort` unknown-purpose fallback:** the closed-set `default → null` with a `console.warn` (:2648) is deliberate and correct (comments :2645-2647). Not a bug.
- **Beta-ui `MutationObserver` on toggles (beta-ui-runtime.js:41):** re-syncs the picker from class changes; on its own benign. Only becomes a bug because classes and flags can diverge (B04-005).
- **Context undercount for Arabic/CJK tokenizer:** explicitly accepted in source comment (:1290-1294). Not a bug.
