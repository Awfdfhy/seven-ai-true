## Bugs Found (Sorted by Severity)

### B03-001 — CRITICAL — VERIFIED
**Affected:** `release/research-runtime.js` → `executeResearch()` / citation emission  
**Symptom:** Deep research responses emit citations with `sourceUrl` but no `retrievedAt` timestamp or content hash, making stale-result detection impossible for users or automated re-validation.  
**Evidence:** Research runtime exports `cite({title,url,snippet})` without temporal metadata. `release/research-runtime.test.cjs` asserts citation shape but does not require `retrievedAt` or `contentHash`. Downstream `intelligence.js` synthesis consumes citations blindly.  
**Reproduction:** Run a research task twice with a mutated source; observe identical citation objects emitted.  
**Fix:** Extend citation schema to `{title,url,snippet,retrievedAt:ISO8601,contentHash:sha256}`; enforce in tests.  
**Regression:** Unit test asserting every emitted citation has non-empty `retrievedAt` and `contentHash`.

---

### B03-002 — HIGH — STRONG
**Affected:** `release/github-self-dev.js` → `searchGitHub()` / result caching  
**Symptom:** GitHub code search results cached in `localStorage` key `seven.github.search.cache` with no TTL or etag validation; subsequent queries serve stale snippets even after upstream repository updates.  
**Evidence:** File shows `localStorage.setItem('seven.github.search.cache', JSON.stringify({q,results,ts:Date.now()}))` but read path lacks `maxAge` check or `If-None-Match` revalidation. `release/control-runtime.js` calls `searchGitHub` without cache-busting parameter.  
**Reproduction:** Search a term, modify a matched file on GitHub, repeat search within 5 min; observe old snippet.  
**Fix:** Add `maxAgeMs` config (default 10 min), store `etag`/`last-modified`, revalidate on read; expose `forceFresh` flag.  
**Regression:** Integration test: write cache, mutate mock GitHub response, assert fresh fetch on re-query.

---

### B03-003 — HIGH — NEEDS_RUNTIME_TEST
**Affected:** `workspaces/research-v2.js` → `deepResearch()` / evidence bundle assembly  
**Symptom:** Evidence bundle returned to UI omits `sourceDocId` linkage for inline citations; UI cannot jump to source paragraph.  
**Evidence:** `research-v2.js` builds `evidence: [{docId, title, url, chunks[]}]` but citation markers in answer text use only numeric indices `[1]` without `data-doc-id`/`data-chunk-id` attributes. `intelligence.js` render path has no mapping from index → `docId`.  
**Reproduction:** Run deep research, inspect answer DOM; citation links lack `data-doc-id`.  
**Fix:** Emit citations as `<cite data-doc-id="…" data-chunk-id="…">[n]</cite>`; add `evidenceMap` to response.  
**Regression:** DOM snapshot test asserting every `<cite>` has both data attributes.

---

### B03-004 — MEDIUM — VERIFIED
**Affected:** `release/execution-bridge.js` → `executeTool()` / web search tool result normalization  
**Symptom:** Web search tool results from native bridge arrive as `{title,url,snippet}` but `execution-bridge` normalizes to `{title,link,snippet}` (key rename `url→link`), breaking downstream citation builder expecting `url`.  
**Evidence:** Line in `execution-bridge.js`: `return {title: r.title, link: r.url, snippet: r.snippet}`. `research-runtime.js` citation builder reads `c.url` → `undefined`.  
**Reproduction:** Invoke web search via control plane; inspect citation object `url` field.  
**Fix:** Normalize to `{title,url,snippet}` consistently; add schema validation in bridge.  
**Regression:** Schema test asserting normalized result has `url` not `link`.

---

### B03-005 — MEDIUM — STRONG
**Affected:** `release/native-bridge.js` → `webSearch` capability / quota & error surfacing  
**Symptom:** Native bridge exposes `webSearch` but swallows HTTP 429/5xx; returns empty array silently, causing research to proceed with zero sources.  
**Evidence:** `native-bridge.js` `webSearch` handler catches all errors, logs, returns `[]`. No `error` field propagated to caller. `control-runtime.js` treats empty array as "no results" not "failure".  
**Reproduction:** Simulate 429 from search API; observe research completes with "no sources found" instead of retry/error UI.  
**Fix:** Return `{results:[], error:{code,message,retryAfter}}`; update callers to surface retry UI.  
**Regression:** Contract test: mock 429, assert bridge returns error object, not empty array.

---

### B03-006 — MEDIUM — NEEDS_RUNTIME_TEST
**Affected:** `workspaces/intelligence.js` → `synthesize()` / citation deduplication  
**Symptom:** Multiple research steps citing the same URL produce duplicate citation entries in final answer; no dedup by `url` or `contentHash`.  
**Evidence:** `intelligence.js` builds `citations` array by concatenating step citations; no `Map` keyed by `url`/`hash`. User sees `[1][2][3]` all pointing to same source.  
**Reproduction:** Run multi-step research hitting same domain; count unique URLs vs citation count.  
**Fix:** Dedup by `url` (or `contentHash` when available) before rendering; preserve all `docId` references.  
**Regression:** Unit test: feed two steps with overlapping URLs, assert output citations length = unique URLs.

---

### B03-007 — LOW — VERIFIED
**Affected:** `release/attachment-runtime.js` → `attachEvidence()` / evidence persistence  
**Symptom:** Evidence attachments stored in `localStorage` under `seven.evidence.{docId}` but never evicted; unbounded growth across sessions.  
**Evidence:** `attachEvidence` writes `localStorage.setItem(key, JSON.stringify({docId,content,ts}))`; no LRU/TTL cleanup. `release/static-audit.cjs` flags 85 `localStorage` refs but no eviction policy.  
**Reproduction:** Run 50+ research tasks; inspect `localStorage` size.  
**Fix:** Add `maxEvidenceBytes` quota (e.g., 5 MB) with LRU eviction on write.  
**Regression:** Stress test writing 10 MB of evidence, assert `localStorage` ≤ quota.

---

### B03-008 — LOW — STRONG
**Affected:** `release/github-self-dev.js` → `selfDevLoop()` / citation freshness in auto-fix PRs  
**Symptom:** Self-dev loop cites files at `HEAD` commit SHA but does not record `fetchedAt`; if PR review takes days, cited lines may have shifted.  
**Evidence:** `github-self-dev.js` builds citation `{file,sha,lineStart,lineEnd}` but no timestamp. GitHub API returns current file content at time of fetch; no `Accept: application/vnd.github.raw+json` with `If-None-Match` on re-read.  
**Reproduction:** Trigger self-dev, wait for upstream change to cited file, re-inspect PR comment; line numbers stale.  
**Fix:** Record `fetchedAt` in citation; on PR update, re-fetch cited ranges with `If-None-Match` and warn if shifted.  
**Regression:** Time-travel test: mock file change between fetch and PR render, assert warning emitted.

## Cross-System Contradictions / Races
1. **Citation key mismatch** (B03-004): `execution-bridge` emits `link`, `research-runtime` expects `url` — silent data loss.
2. **Cache vs. freshness** (B03-002 vs B03-001): GitHub search cache has no TTL; research citations have no `retrievedAt` — two layers of stale-result blindness.
3. **Error swallowing** (B03-005): Native bridge hides 429; control plane treats as "no results" — user sees false negative, no retry affordance.
4. **Evidence map missing** (B03-003): Research v2 produces evidence bundle but UI citation markers lack back-references — breaks source-jump UX.
