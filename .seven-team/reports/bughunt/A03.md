## 3. Findings

### A03-001 — CRITICAL — Composer resize race: legacy `autoGrowInput` fights shell keyboard resize
- **Surface:** `#userInput` textarea in `seven_ai-final.html:836-837`
- **Symptom:** Composer jumps, collapses, or freezes during Arabic IME composition; height may lag keyboard open/close on Android.
- **Evidence:** Two independent resize systems mutate the same element:
  - `seven_ai-final.html:837` inline `oninput="autoGrowInput(this)"` sets height to `scrollHeight` with no cap; CSS `max-height:160px` applies later but can fire after visual update.
  - `release/workspaces/seven-shell.js:37-38` `resizeInput()` caps height to `max(120, min(viewport*.34, 320))` and listens to input/focus/blur.
  - Inline handler runs first, potentially writing unbounded height; shell handler then clamps. On rapid IME composition, this can oscillate per input event.
- **Reproduction:** Open app on Android RTL Arabic, focus composer, type multi-line with IME; height flickers or exceeds safe area.
- **Fix direction:** Remove inline `oninput` resize; keep shell `resizeInput` only. Inline handler should not mutate geometry.
- **Regression test:** Instrumented test asserting `#userInput` height monotonic within 1px during simulated composition input + soft-keyboard show.

### A03-002 — CRITICAL — Enter-to-send breaks under IME composition on Arabic keyboards
- **Surface:** `#userInput` `onkeydown` in `seven_ai-final.html:837`
- **Symptom:** Partial Arabic phrase or composed text is sent prematurely, producing truncated message.
- **Evidence:** Guard `event.isComposing` is not reliable on all Android WebView targets; older Android or some input methods omit `isComposing` or fire Enter before `compositionend`. The guard also runs in inline handler, but `sendMessage()` locks are not synchronized with composition lifecycle. There is no `compositionstart`/`compositionend` lock.
- **Reproduction:** Arabic T9/Google Arabic keyboard, long word with Enter for word boundary; some methods emit Enter with `isComposing===false` during active composition.
- **Fix direction:** Add a `composition`-aware send lock; prefer explicit send button on touch devices; do not rely solely on `isComposing`.
- **Regression test:** Automated composition sequence with keyboard events; assert message not sent until composition ends.

### A03-003 — HIGH — Main shell surfaces lack RTL mirror rules; `rtl.css` covers workspaces only
- **Surface:** `release/seven-final.css`, `release/beta-ui.css`, `release/workspaces/rtl.css`
- **Symptom:** Under `lang="ar"`/`dir="rtl"`, topbar icons, sidebar arrows, composer padding, and message action buttons remain visually LTR; some components clip on narrow widths.
- **Evidence:**
  - `release/workspaces/rtl.css` contains only 3 `html[dir=rtl]` overrides: `.seven-ws-kicker`, `.seven-ws-head h1`, `.seven-ws-actions` — all workspace-internal.
  - Wave-01 A01 report explicitly notes: "rtl.css holds only 4 `.seven-ws-*` rules; none for sidebar, primary nav, topbar, modal."
  - `seven-final.css` uses physical `border-right-color` for `.sidebar` and left-padded `.composer`; no `border-inline-*` or RTL overrides.
  - `release/beta-ui.css:18` does mirror `.message.user .bubble` radius, but shell-level geometry is not direction-safe.
- **Reproduction:** `document.documentElement.lang='ar'; document.documentElement.dir='rtl'` on 360×800; inspect composer padding, topbar title alignment, and room list bullets/arrows.
- **Fix direction:** Add shell-level RTL overrides for topbar, sidebar, input-area, composer, and empty state using logical properties or `[dir=rtl]` rules.
- **Regression test:** Deterministic screenshot matrix: `dir=ltr/rtl` × `day/night` × `[320,360]` width, assert no directional clipping in composer/topbar.

### A03-004 — MEDIUM — Empty state is untranslated if created before `localizeShell` runs
- **Surface:** `release/workspaces/seven-shell.js:ensureEmpty()` and `localizeShell()`
- **Symptom:** Fresh install with Arabic locale shows English empty state ("What can Seven do for you?") while later strings are Arabic.
- **Evidence:** `ensureEmpty()` injects hardcoded English HTML string and appends it. `localizeShell()` localizes strings only if `.seven-shell-empty` already exists; if empty state is created after `localizeShell()` by a mutation, it stays English until next sync. Mutation observer `sync` re-runs `ensureEmpty()`, but if `ensureEmpty()` short-circuits on existing node, text is never re-localized on locale change.
- **Reproduction:** Set `lang=ar` + empty room list; inspect empty state text content.
- **Fix direction:** Make `ensureEmpty()` use localized strings on creation; update existing empty state on locale change in `localizeShell()`.
- **Regression test:** Playwright: set `lang=ar`, empty history, assert empty state text contains Arabic script.

### A03-005 — MEDIUM — Arabic text in assistant bubbles can horizontally overflow narrow viewports
- **Surface:** `#chat .bubble.markdown` / `.content` in `seven_inal.html`
- **Symptom:** Long Arabic words or code fences cause document `scrollWidth > innerWidth`; settings modal clips.
- **Evidence:** `release/release-verify.cjs` includes a dedicated regression test "long messages code and URLs cannot widen the mobile viewport" that passes for ASCII URLs/code blocks, but there is no equivalent long unbroken Arabic word or RTL markdown test. `release/workspaces/rtl.css` adds `overflow-wrap:anywhere` to `.seven-ws-source` and `.seven-rpg-contract dd`, but chat bubbles rely on `.bubble.markdown { white-space: normal; }` without `overflow-wrap:anywhere`.
- **Reproduction:** Send single Arabic word > 300 chars in 320px width; scrollWidth grows beyond viewport.
- **Fix direction:** Add `overflow-wrap:anywhere`/`word-break:break-word` to chat bubble selectors; add RTL long-word test in release verify.
- **Regression test:** Deterministic DOM test in `release/release-verify.cjs`: append 18 assistant messages with long Arabic words in `dir=rtl`; assert `scrollWidth <= innerWidth+2`.

### A03-006 — LOW — Default `maxTokens` UI value is misleadingly large on small screens
- **Surface:** `#maxTokens` input in `seven_ai-final.html:902`
- **Symptom:** Mobile settings shows `65536` without locale-aware formatting; in Arabic it may occupy most of the modal width.
- **Evidence:** Input has no `maxlength` constraint beyond browser default; long numeric string in RTL can increase label width. No `aria-describedby` link to helper.
- **Reproduction:** 320px viewport, `lang=ar`, open Settings; observe long numeric input overflow or truncation.
- **Fix direction:** Format number with thousand separators via JS, or cap displayed value to actual route limit on open.
- **Regression test:** Assert settings modal bounded on 320px RTL after opening Settings.

### A03-007 — LOW — Regenerate button text is hardcoded English
- **Surface:** `renderRegenerateButton()` in `seven_ai-final.html`
- **Symptom:** Arabic users see "Regenerate" with no Arabic equivalent.
- **Evidence:** Button injected without i18n helper; other surfaces use `T()` / `Q()` helpers.
- **Reproduction:** Generate assistant message in Arabic UI; inspect regenerate button.
- **Fix direction:** Reuse existing Arabic label helpers.
- **Regression test:** Assert regenerate button text contains Arabic script when `lang=ar`.

## 4. Cross-system contradictions / races
- **Resize race:** Inline `autoGrowInput` and `resizeInput` both write `textarea.style.height` in same event loop. Also CSS `max-height` and JS `resizeInput` cap to 320px, but inline handler ignores viewport keyboard state.
- **Locale initialization race:** `SevenRemake` boot sets `lang`/`dir` from persisted language, but shell/attachment boot order may localize placeholders before `documentElement.lang` is set in some browser back/forward cache restores.
- **Settings control race:** `onModelChange` resets `#maxTokens`/`#reasoningEffort` DOM values silently; `localizeShell` does not run on Settings tab changes, so untranslated labels can persist after switching tabs.
