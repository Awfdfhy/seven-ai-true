## Bugs Found (Sorted by Severity)

### B01-001  CRITICAL  VERIFIED
**Surface:** `release/beta-ui-runtime.js:36` — `installStopFix()` stopGeneration patch  
**Symptom:** Stop button press sets `stopRequested=true` but variable is undeclared (`stopRequested` vs `requested`), causing ReferenceError in non-Android path; Android path nulls `activeAbortController` instead of aborting, leaving in-flight streams uncancelled.  
**Evidence:** Line 36: `let requested=false; try{stopRequested=true; requested=true}catch(_){}` — `stopRequested` never declared. Line 36 Android branch: `activeAbortController=null` without `.abort()`.  
**Reproduction:** Load app, start generation, press Stop; observe console ReferenceError (non-Android) or stream continues (Android).  
**Fix:** Use declared `requested` variable; call `activeAbortController?.abort()` on Android too.  
**Regression:** Unit test patching `r.stopGeneration` verifying abort called and no ReferenceError.

---

### B01-002  HIGH  VERIFIED
**Surface:** `apk/patch-android.cjs:110-111` — Double-send test proves race in `sendMessage`  
**Symptom:** Two concurrent `sendMessage()` calls can append two identical user messages to room history.  
**Evidence:** Test explicitly checks `Promise.all([sendMessage(),sendMessage()])` and expects exactly 1 user message with content `ci-double-send`; test exists because bug occurs.  
**Reproduction:** Call `sendMessage()` twice before first resolves (e.g., double-click send, or programmatic double-call).  
**Fix:** Add guard in `sendMessage` — reject/ignore if a send is already in-flight for that room.  
**Regression:** The existing double-send test in `patch-android.cjs` must pass; add unit test for guard.

---

### B01-003  HIGH  STRONG
**Surface:** `release/attachment-runtime.js:28` — `patchSend()` wraps `r.sendMessage`  
**Symptom:** Attachment selection cleared in `finally` block even if original `sendMessage` throws, but wrapper doesn't re-throw — callers see resolved promise instead of rejection.  
**Evidence:** `wrapped=async function(){try{return await original.apply(this,arguments)}finally{clearSelection()}}` — missing `throw` after `finally` completes on error path.  
**Reproduction:** Attach file, trigger send that fails (network error); observe caller receives undefined instead of rejection.  
**Fix:** Re-throw caught error after `clearSelection()` in `catch` block, or use `try/catch/finally` with re-throw.  
**Regression:** Test that failed send with attachment propagates error to caller.

### B01-004  MEDIUM  STRONG
**Surface:** `release/beta-ui-runtime.js:36` — Android abort handling diverges from web  
**Symptom:** On Android, `activeAbortController` is nulled but not aborted; native layer may not observe abort signal, causing orphaned native requests.  
**Evidence:** Non-Android path calls `activeAbortController.abort()`; Android path only `activeAbortController=null`. Comment says "androidSafe" but no abort occurs.  
**Reproduction:** Start generation on Android, press Stop, verify native request cancelled (requires runtime).  
**Fix:** Ensure Android abort signal propagated to native bridge (e.g., via `control-bridge.js` or native call).  
**Regression:** Integration test: stop during streaming on Android asserts native request terminated.

### B01-005  MEDIUM  NEEDS_RUNTIME_TEST
**Surface:** Room switching — `apk/patch-android.cjs:98` waits for `roomPersistence.status().ready`  
**Symptom:** No evidence that switching rooms preserves in-flight generation state, aborts cleanly, or restores scroll/attachment state.  
**Evidence:** Only persistence readiness checked; no `roomPersistence` source in evidence. Room switch may leak abort controllers, leave stale attachments, or duplicate history.  
**Reproduction:** Start generation in Room A, switch to Room B, switch back — check for duplicate messages, lost attachments, or crashed stream.  
**Fix:** On room switch: abort current generation, persist draft/attachments per room, restore on return.  
**Regression:** Automated room-switch stress test (10 rapid switches during generation).

### B01-006  MEDIUM  NEEDS_RUNTIME_TEST
**Surface:** Streaming retry — `cloudflare/search-gateway/worker.mjs:81-92` AbortController wiring

### B01-007  LOW  VERIFIED
**Surface:** `release/beta-ui-runtime.js:23` — `m()` mode derivation reads DOM toggles  
**Symptom:** Mode (`chat`/`think`/`search`/`research`) derived from toggle button `.active` class at call time; if toggles change async, `sendMessage` may read stale mode.

## Cross-System Contradictions / Races
1. **Stop vs Send race:** `installStopFix` patches `r.stopGeneration`; `patchSend` patches `r.sendMessage`. Both mutate `r` (likely `window.SevenShell` or similar). No coordination — stop during send may clear attachment selection while send still in-flight.
2. **Android vs Web abort divergence:** `beta-ui-runtime.js` treats Android as special case but doesn't actually abort; native bridge (`materialize-native-platform.cjs`) has no visible abort handler for in-flight requests.
3. **Room persistence vs attachment state:** `roomPersistence` readiness checked but attachment runtime (`S.lastSelection`) is global, not per-room.

## Missing / Error States
- No visible error boundary for `sendMessage` failures (network, abort, quota) — user sees no toast/retry.
- `activeAbortController` global — concurrent generations (multi-room?) would share single controller.
- `roomPersistence` API not in evidence — cannot verify save/restore of draft, attachments, scroll, mode.
- Streaming chunk handling not in evidence — no `ReadableStream` consumer shown for assistant messages.
