# B05 Bug Audit Report — RPG / Canon / World Runtime / State / Titles / Persistence

## Areas Inspected
- Exact 2.4.3 target manifest identifying the RPG/world workspace payload.
- `release/workspaces/rpg.js`: world/canon session ownership, title recording, pack loading and workspace lifecycle.
- `release/world-runtime.js`: session creation, beat commits, branch rules and title recording.
- `release/workspaces/seven-shell.js` and main conversation persistence for adjacent persistence/workspace integration.

## Bugs Found — Sorted by Severity

### B05-001 — RPG world/canon progress and titles have no durable persistence path
- **Severity:** CRITICAL
- **Confidence:** STRONG
- **Affected surface:** `release/workspaces/rpg.js` — state object `S`, `snapshot()`, `loadWork()`, `loadCanon()`
- **User-visible symptom:** loaded world/canon state, beat progress, branch metadata and recorded titles can disappear after WebView/app reload unless another uninspected native layer persists them.
- **Evidence / root cause:** authoritative RPG state is stored in module-memory fields `S.worldEngine`, `S.worldSession`, `S.canonEngine`, `S.canonSession`. `snapshot()` only returns an object. The inspected RPG runtime contains no localStorage/IndexedDB save/restore path, and the inspected main room persistence does not reference `SevenRpgWorkspace.snapshot()`.
- **Minimal reproduction / deterministic test idea:** load a world pack, commit a verified beat, record a title, reload/restart, reopen RPG and compare the resulting snapshot.
- **Fix direction:** add versioned canonical RPG persistence keyed to the owning room/project/work, with migration and corruption handling.
- **Regression test:** restart/reload round-trip for world session, canon session, titles, branch metadata and pack identity.

### B05-002 — `snapshot()` exposes live mutable session references and can bypass verification-gated APIs
- **Severity:** HIGH
- **Confidence:** VERIFIED
- **Affected surface:** `release/workspaces/rpg.js` — `snapshot()`
- **User-visible symptom:** adjacent runtime code can silently alter RPG/canon progress without going through `commitVerifiedBeat()` or `applyVerifiedDelta()`.
- **Evidence / root cause:** `snapshot()` returns `worldSession:S.worldSession` and `canonSession:S.canonSession` directly rather than defensive clones/frozen projections. The internal runtime continues using those same objects.
- **Minimal reproduction / deterministic test idea:** call `const s=SevenRpgWorkspace.snapshot(); s.worldSession.beatIndex=999;` and then inspect `currentContract()`/subsequent state.
- **Fix direction:** return deep-cloned/frozen snapshots and keep canonical session references private.
- **Regression test:** mutation of any returned snapshot must not mutate internal canonical state.

### B05-003 — Loading a new world/canon pack replaces current progress with no destructive-action guard
- **Severity:** HIGH
- **Confidence:** VERIFIED
- **Affected surface:** `loadWork()`, `loadCanon()`, JSON file handlers
- **User-visible symptom:** choosing another valid pack immediately replaces the active in-memory session and can discard progress.
- **Evidence / root cause:** `loadWork` creates a new engine and assigns a fresh session immediately; `loadCanon` does the same for canon. There is no dirty-state check, save/export checkpoint, confirmation or rollback around replacement.
- **Minimal reproduction / deterministic test idea:** progress a session and create titles, then load a different valid pack and verify that the previous session is no longer reachable through the workspace.
- **Fix direction:** make pack replacement transactional and require save/export/confirmation when current state is dirty.
- **Regression test:** cancelled or failed replacement preserves state; accepted replacement creates a recoverable checkpoint.

### B05-004 — Title numbering is count-based and allows duplicate episode/chapter numbers with different names
- **Severity:** MEDIUM
- **Confidence:** VERIFIED
- **Affected surface:** `nextTitleNumber()`, `normalizedTitleMeta()`, `recordTitle()`
- **User-visible symptom:** two entries can both be “Episode 2” (or the same chapter number) if their names differ; later auto-numbering can become non-monotonic/confusing.
- **Evidence / root cause:** the next number is `count(kind)+1`, not the maximum existing number + 1. Duplicate detection compares the full formatted title string, not `kind + numeric identity`.
- **Minimal reproduction / deterministic test idea:** manually record `Episode 2 — A`, then record `Episode 2 — B`; both formatted strings differ and therefore pass duplicate-title checking.
- **Fix direction:** store number metadata explicitly and enforce a numbering/uniqueness policy independently from display text.
- **Regression test:** manual gaps, repeated numbers, mixed title kinds, imported sessions and subsequent auto-numbering.

### B05-005 — RPG pack loading parses the entire selected JSON with no byte/depth budget
- **Severity:** MEDIUM
- **Confidence:** STRONG
- **Affected surface:** `jsonFile()`, `loadWork()`, `loadCanon()`
- **User-visible symptom:** a very large/adversarial local pack can freeze the main thread or exhaust memory on mobile.
- **Evidence / root cause:** `jsonFile` performs `JSON.parse(await file.text())` on the whole file without a size budget. World normalization then clones/normalizes the structure again.
- **Minimal reproduction / deterministic test idea:** select progressively larger valid JSON packs on the target Android device and measure main-thread stall/memory.
- **Fix direction:** enforce byte/count/depth limits before full processing and reject oversized packs with a clear error.
- **Regression test:** oversized pack rejected before expensive parse/normalization; upper-bound valid pack remains responsive.

### B05-006 — Copy-button MutationObserver rescans the full RPG chat on every subtree mutation
- **Severity:** LOW
- **Confidence:** VERIFIED
- **Affected surface:** `observeChat()`, `scanCopy()`, `messageNodes()`
- **User-visible symptom:** long RPG sessions can accumulate avoidable DOM work/stutter while messages stream or render.
- **Evidence / root cause:** the observer watches `#chat` with `childList:true, subtree:true`; each mutation calls `scanCopy()`, which queries/filters the complete message collection again.
- **Minimal reproduction / deterministic test idea:** populate hundreds of messages, stream a response, and count selector scans/long tasks per mutation.
- **Fix direction:** process only added nodes or debounce/batch observer work.
- **Regression test:** DOM work per update should scale with changed nodes rather than total history length.

## Cross-System Contradictions / Races
- Main conversations have a canonical persistence boundary, while the inspected RPG workspace has no equivalent durable boundary.
- Verification-gated mutation APIs exist, but live snapshot references expose a path around those gates.
- Pack replacement is destructive while durable RPG checkpointing is not established.

## Missing / Error States
- No versioned RPG save/restore/migration contract in the inspected runtime.
- No dirty-state or transactional pack replacement.
- No explicit numeric title identity/uniqueness policy.
- No bounded pack-size validation.

## False Positives Rejected
- `SevenWorld.commitBeat()` does enforce order/player-agency rules; those gates are not reported as broken.
- Exact duplicate formatted titles are blocked.
- Workspace unmount disconnects its observer and removes its registered listeners.

## Top 5 Highest-Priority Bugs
1. **B05-001** — RPG/canon state lacks a proven durable persistence path.
2. **B05-002** — mutable snapshots bypass verification boundaries.
3. **B05-003** — pack replacement can discard active progress.
4. **B05-004** — duplicate/non-monotonic title numbering.
5. **B05-005** — unbounded JSON pack processing on mobile.
