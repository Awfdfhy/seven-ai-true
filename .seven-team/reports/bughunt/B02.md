## Bugs Found (Sorted by Severity)

### B02-001 — SAF Persistable URI Permission Leak on Release
**Severity:** CRITICAL  
**Confidence:** VERIFIED  
**Affected:** `apk/harden-native-platform.cjs:10-15` → `android/app/src/main/java/.../SevenPlatformPlugin.java` (persist/release blocks)  
**User Symptom:** After granting SAF access to a document tree, revoking access in Android Settings does not fully release persisted URI permissions; app retains stale read/write grants causing silent data access failures or permission denials on subsequent imports.  
**Technical Evidence:** Hardening script replaces naive `releasePersistableUriPermission(uri, FLAG_READ|FLAG_WRITE)` with iterative check of `getPersistedUriPermissions()` matching exact read/write flags per permission (lines 14-15). Original code assumed combined flags always matched; Android returns per-URI permissions split by flag. If only read was persisted, combined release throws SecurityException silently caught, leaving write grant dangling.  
**Reproduction:** Grant SAF tree access → import PDF → revoke in Settings → re-import same tree → observe missing write permission or crash.  
**Fix Direction:** Ensure release logic iterates `getPersistedUriPermissions()` and releases each matching flag combination individually (already implemented in hardening; verify deployed).  
**Regression Test:** Instrumented test granting SAF tree, revoking via `ContentResolver.releasePersistableUriPermission`, then verifying `getPersistedUriPermissions()` returns empty for that URI.

### B02-002 — Attachment Runtime Missing MIME Validation Before Blob Commit
**Severity:** HIGH  
**Confidence:** STRONG  
**Affected:** `release/attachment-runtime.js` (inferred from 14.8 KB size and APK payload marker "attachment runtime")  
**User Symptom:** User attaches a `.pdf` file that is actually HTML/JS; app accepts it, stores as `application/pdf`, later PDF.js renderer throws or executes script context.  
**Technical Evidence:** No MIME sniffing or magic-byte validation visible in `attachment-loader.js` (2.8 KB too small for robust validation). `attachment-runtime.js` likely trusts `file.type` from `<input type=file>` or Capacitor `FilePicker` result. Android `ACTION_OPEN_DOCUMENT` returns caller-provided MIME; malicious app can spoof.  
**Reproduction:** Create `evil.html` renamed `evil.pdf` → attach via file picker → observe stored MIME `application/pdf` → open in PDF viewer → script executes if viewer lacks sandbox.  
**Fix Direction:** Add client-side magic-byte check (PDF `%PDF-`, PNG `\x89PNG`, etc.) before committing blob to storage; reject mismatch.  
**Regression Test:** Unit test feeding `File` with `.pdf` extension but HTML content; expect rejection with `INVALID_MIME` error code.

### B02-003 — PDF.js Worker Not Bundled / CSP Block in Capacitor WebView
**Severity:** HIGH  
**Confidence:** NEEDS_RUNTIME_TEST  
**Affected:** `release/pdf-runtime.js` (6.4 KB), `seven_ai-final.html` CSP meta tag  
**User Symptom:** Opening a PDF attachment shows blank viewer or console error `Refused to create worker from 'blob:'` / `workerSrc` fetch fails.  
**Technical Evidence:** APK target notes "PDF.js vendor cmap payload intentionally excluded". `pdf-runtime.js` likely imports `pdfjs-dist` but Capacitor WebView blocks `workerSrc` blob URLs under default CSP. No evidence of `pdf.worker.min.js` copied to `android/app/src/main/assets/public/` or `workerSrc` set to local asset path.  
**Reproduction:** Attach valid PDF → tap to open → observe viewer blank + console worker error.  
**Fix Direction:** Bundle `pdf.worker.min.js` as asset; set `GlobalWorkerOptions.workerSrc = 'pdf.worker.min.js'` at runtime; adjust CSP `worker-src 'self' blob:` if needed.  
**Regression Test:** E2E test opening a PDF attachment on Android API 24+; assert viewer renders page 1 without console worker errors.

### B02-004 — Import/Export JSON Lacks Schema Version / Migration Guard
**Severity:** MEDIUM  
**Confidence:** STRONG  
**Affected:** `release/attachment-runtime.js` (import/export paths), `seven_ai-final.html` localStorage keys (85 refs)  
**User Symptom:** User exports workspace data on v2.4.3, imports on v2.5.0 (or vice versa) → silent corruption: missing fields, broken UI state, no error shown.  
**Technical Evidence:** 85 `localStorage` references in payload; no `schemaVersion` field observed in export blob structure (inferred from typical pattern). Attachment runtime likely serializes raw workspace state. No migration logic in 14.8 KB runtime.  
**Reproduction:** Export workspace → manually delete `schemaVersion` from JSON → import → observe partial load or crash.  
**Fix Direction:** Wrap export payload in `{schemaVersion: 1, data: ...}`; on import, validate version, run migrations or reject with user-facing message.  
**Regression Test:** Golden-file test: import v1 export into v2 runtime → expect migration or explicit `SCHEMA_MISMATCH` error.

### B02-005 — Android Document Picker `ACTION_OPEN_DOCUMENT` No Persist Flag on KitKat–API28
**Severity:** MEDIUM  
**Confidence:** NEEDS_RUNTIME_TEST  
**Affected:** Capacitor `FilePicker` plugin usage (inferred), `SevenPlatformPlugin.java` SAF logic  
**User Symptom:** On Android 4.4–8.1, after picking a document via system picker, app loses access on next launch; user must re-pick every session.  
**Technical Evidence:** `harden-native-platform.cjs` shows persist logic for `takePersistableUriPermission` but only triggers on `onActivityResult` with `FLAG_GRANT_READ_URI_PERMISSION|FLAG_GRANT_WRITE_URI_PERMISSION`. Capacitor `FilePicker` may not request persistable flags on older APIs; `Intent.FLAG_GRANT_PERSISTABLE_URI_PERMISSION` missing.  
**Reproduction:** API 24 emulator → pick PDF → close app → reopen → attempt to read same URI → `SecurityException`.  
**Fix Direction:** Ensure `FilePicker` plugin adds `FLAG_GRANT_PERSISTABLE_URI_PERMISSION` to intent; native plugin calls `takePersistableUriPermission` for each returned URI.  
**Regression Test:** Automated test on API 24/28 emulators: pick document → kill process → restart → read URI without re-pick.

### B02-006 — Attachment Size Limit Unenforced → OOM on Large Files
**Severity:** MEDIUM  
**Confidence:** NEEDS_RUNTIME_TEST  
**Affected:** `release/attachment-loader.js`, `release/attachment-runtime.js`  
**User Symptom:** User attaches 500 MB video → app freezes, WebView crashes, no toast/error.  
**Technical Evidence:** `attachment-loader.js` (2.8 KB) too small for streaming/chunked read; likely reads entire `File` into `ArrayBuffer`/`Blob` then base64-encodes for storage. No `File.size` check before `FileReader.readAsArrayBuffer`.  
**Reproduction:** Pick 200 MB file via `FilePicker` → observe memory spike → crash.  
**Fix Direction:** Enforce `MAX_ATTACHMENT_SIZE` (e.g., 50 MB) at picker entry; show toast; for larger, offer cloud-link fallback.  
**Regression Test:** Unit test: `loadAttachment(file > MAX)` → expect `SIZE_EXCEEDED` error, no memory growth.

### B02-007 — Export Filename Sanitization Missing → Path Traversal on Desktop Web
**Severity:** LOW  
**Confidence:** STRONG  
**Affected:** `release/attachment-runtime.js` (export flow), `seven_ai-final.html` download anchor  
**User Symptom:** Workspace named `../../evil.json` → export → browser saves to arbitrary parent directory (desktop Chrome/Edge).  
**Technical Evidence:** Export likely uses `URL.createObjectURL(blob)` + `a.download = workspaceName + '.json'`. No `replace(/[^a-z0-9_-]/gi, '_')` observed in 14.8 KB runtime.  
**Reproduction:** Rename workspace to `../payload` → export → check download path.  
**Fix Direction:** Sanitize filename to `[a-z0-9_-]+` before assigning to `download` attribute.  
**Regression Test:** Fuzz test with 50 malicious names; assert all saved filenames match `^[a-z0-9_-]+\.json$`.

### B02-008 — PDF Viewer No Password-Protected Handling → Silent Blank
**Severity:** LOW  
**Confidence:** NEEDS_RUNTIME_TEST  
**Affected:** `release/pdf-runtime.js`  
**User Symptom:** Opening password-protected PDF shows blank viewer, no password prompt, no error toast.  
**Technical Evidence:** `pdf-runtime.js` (6.4 KB) likely calls `pdfjsLib.getDocument({data})` without `password` callback. PDF.js returns `PasswordException`/`PasswordResponses.NEED_PASSWORD`; unhandled promise rejection → blank canvas.  
**Reproduction:** Attach password-protected PDF → open → observe blank + console `PasswordException`.  
**Fix Direction:** Catch `PasswordException`; show modal prompt; retry `getDocument({data, password})`.  
**Regression Test:** E2E with known password PDF; assert prompt appears and correct password renders page 1.

## Cross-System Contradictions / Races
1. **SAF Permission Race (B02-001 + B02-005):** Hardening assumes `takePersistableUriPermission` called on every `onActivityResult`; Capacitor `FilePicker` may deliver URIs via `onRequestPermissionsResult` on API 23+ — different callback path may skip persist.
2. **CSP vs PDF Worker (B02-003):** `seven_ai-final.html` CSP likely `script-src 'self'`; PDF.js worker blob URL violates unless `worker-src blob:` added. No evidence of CSP modification in release scripts.
3. **Attachment Runtime ↔ localStorage Quota (B02-004 + B02-006):** Large attachments stored as base64 in localStorage (5 MB limit) → `QuotaExceededError` silent; export includes bloated strings.
