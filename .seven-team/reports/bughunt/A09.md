## Bugs Found (Sorted by Severity)

### A09-001 | CRITICAL | VERIFIED
**Surface:** `beta-ui-runtime.js:36` `installStopFix()` / `stopGeneration` patch
**Symptom:** Stop button becomes permanently disabled after first use; generation cannot be stopped again
**Root Cause:** Line 36-37: `stopRequested` variable referenced but never declared (`let stopRequested=true` inside try block shadows nothing; `requested` assigned but `stopRequested` read). The `MutationObserver` on stop button (line 52-55) calls `resetStopButton()` when button is hidden, but `resetStopButton()` (line 35) only re-enables if button has `.seven-stopping` class or `data-seven-stopping` attribute. After first stop, `stopGeneration` sets these but never clears them on completion.
**Evidence:** 
```js
// Line 44-45: stopRequested used but never declared in scope
let requested=false;
try{stopRequested=true;requested=true}catch(_){}
// Line 52-55: Observer triggers resetStopButton on hide
S.stopObserver=new MutationObserver(()=>{const hidden=...;if(hidden)resetStopButton()})
// Line 35: resetStopButton only acts if stopping markers present
if(!stop.disabled&&!stop.classList.contains('seven-stopping')&&!stop.dataset.sevenStopping)return;
```
**Repro:** Start generation → click stop → wait for completion → start new generation → click stop (button unresponsive)
**Fix:** Declare `stopRequested` properly; clear stopping markers in `resetStopButton`; ensure `stopGeneration` original is called
**Regression:** E2E test: 3 consecutive generate/stop cycles; assert stop button clickable each time

### A09-002 | HIGH | VERIFIED
**Surface:** `beta-ui-runtime.js:39` `installMessageArrival()` / `MutationObserver` on `#chat`
**Symptom:** Memory leak in long chats; `messageObserver` never disconnected on navigation/chat switch
**Root Cause:** Line 62-63: `S.messageObserver` created but no cleanup when chat container replaced (e.g., room switch). `S.messageObserver.disconnect()` only called at start of `installMessageArrival()` (line 61), not on teardown. Each room switch adds new observer; old chat nodes retained in closure.
**Evidence:** 
```js
// Line 61-63: Disconnect only at install time, not on chat replacement
if(S.messageObserver)S.messageObserver.disconnect();
S.messageObserver=new MutationObserver(...);
S.messageObserver.observe(chat,{childList:true,subtree:true});
```
**Repro:** Switch rooms 10× → heap snapshot shows 10 `MutationObserver` instances + detached message nodes
**Fix:** Expose `cleanupMessageObserver()`; call on room change; use `AbortSignal` pattern
**Regression:** Test: 20 room switches → `MutationObserver` count ≤ 1

### A09-003 | HIGH | STRONG
**Surface:** `attachment-loader.js:8-16` `load()` promise caching / `S.loading` state
**Symptom:** Attachment runtime load fails silently on network error; subsequent calls return rejected promise permanently
**Root Cause:** Line 8: `if(S.loading)return S.loading` caches promise. Line 13: `fail()` sets `S.loading=null` but promise already rejected. Line 22: `load().catch(()=>{})` swallows error. Subsequent calls create new promise but race condition: if first load pending, second caller gets same rejected promise.
**Evidence:**
```js
// Line 8: Returns cached promise (pending or rejected)
if(S.loading)return S.loading;
// Line 14: fail() nulls S.loading AFTER reject
function fail(){S.loading=null;reject(...)}
// Line 22: Fire-and-forget with empty catch
load().catch(function(){});
```
**Repro:** Offline → click attach → wait for timeout → go online → click attach (fails immediately)
**Fix:** Don't cache rejected promises; reset `S.loading=null` before creating new promise; expose `reset()` method
**Regression:** Network fail → recover → load succeeds

### A09-004 | HIGH | VERIFIED
**Surface:** `beta-ui-runtime.js:17-21` `f()`/`a()` theme timer / `localStorage` access
**Symptom:** Theme auto-switch timer fires at wrong time after system sleep/wake; `localStorage` throws in private browsing
**Root Cause:** Line 20: `setTimeout` calculated once at boot (`a()`). If laptop sleeps past 6am/6pm boundary, timer fires at stale calculated delay. Line 17: `localStorage.getItem` throws in Safari private mode / storage full - caught but returns `'auto'` silently, losing user preference.
**Evidence:**
```js
// Line 17: try/catch swallows all errors
try{p=localStorage.getItem('theme')}catch(e){return'auto'}
// Line 20: Single timeout, no resilience to sleep/wake
S.themeTimer=setTimeout(()=>{t(1);a()},Math.max(1000,b-n))
```
**Repro:** Set theme=day → sleep past 6pm → wake → theme doesn't switch until manual interaction
**Fix:** Use `visibilitychange` + `setInterval` polling; persist preference to `sessionStorage` fallback
**Regression:** Sleep/wake cycle test; private browsing test
