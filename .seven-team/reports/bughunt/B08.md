## Bugs Found (by Severity)

### B08-001 — CRITICAL — VERIFIED
**Surface:** `localStorage` persistence / session recovery (all workspaces)  
**Symptom:** No `sessionStorage` usage (0 refs) + 85 `localStorage` refs → cold-start loses in-flight turn state; refresh mid-stream discards partial assistant response.  
**Evidence:** APK target static scan shows 0 `sessionStorage`; `wave-01-b09-recovery.yml:53` greps for `sessionStorage|persist|save|restore` — only `localStorage` hits.  
**Reproduction:** Start a long generation → refresh page before completion → observe lost turn.  
**Fix:** Dual-write critical turn state to `sessionStorage` (survives refresh) and `localStorage` (survives close).  
**Regression:** Playwright test: navigate → stream → reload → assert last user/assistant pair intact.

### B08-002 — HIGH — STRONG
**Surface:** `native-bridge.js` ↔ Android WebView storage quota  
**Symptom:** Large conversation history (>5 MB) triggers `QuotaExceededError` on `localStorage.setItem`; no catch/fallback → silent data loss.  
**Evidence:** `native-bridge.js` hash `44ae55c9…` is the only native bridge; Capacitor/WebView default quota ~5–10 MB. No `try/catch` around `localStorage` in static grep.  
**Reproduction:** Inject 6 MB JSON into `localStorage.seven_history` → call bridge save → observe exception in logcat.  
**Fix:** Wrap all `localStorage.setItem` in `try/catch`; on quota, prune oldest turns (LRU) and retry.  
**Regression:** Unit test: mock `localStorage` to throw `QuotaExceededError` → verify prune+retry succeeds.

### B08-003 — HIGH — NEEDS_RUNTIME_TEST
**Surface:** APK upgrade migration (2.4.2 → 2.4.3)  
**Symptom:** No versioned migration script in evidence; `android-apk.yml` installs fresh debug APK, never tests upgrade path.  
**Evidence:** `android-apk.yml:64-71` runs `android:generate` + `connectedDebugAndroidTest` on clean emulator. No `adb install -r` upgrade step.  
**Reproduction:** Install 2.4.2 release APK → populate data → `adb install -r 2.4.3.apk` → launch → check `localStorage` schema version.  
**Fix:** Add `migrations/` module with `upgarde(localStorage, fromVer, toVer)`; run on first load.  
**Regression:** CI job: install old APK → seed data → upgrade → assert data intact + schema version bumped.

### B08-004 — MEDIUM — STRONG
**Surface:** `attachment-runtime.js` (hash `aa2ac0a1…`) — blob cleanup on session restore  
**Symptom:** Object URLs created for attachments (`URL.createObjectURL`) never revoked on restore → memory leak across sessions.  
**Evidence:** Attachment runtime is separate payload; no `URL.revokeObjectURL` in static grep of evidence.  
**Reproduction:** Load 10 images → refresh → heap snapshot shows 10 unreleased blob URLs.  
**Fix:** Track created URLs in `sessionStorage`; revoke on `beforeunload` and restore.  
**Regression:** DevTools memory test: attach → reload → assert `URL.revokeObjectURL` called for each prior blob.

### B08-005 — MEDIUM — NEEDS_RUNTIME_TEST
**Surface:** `github-self-dev.js` (hash `f9403357…`) — self-update backup rollback  
**Symptom:** Self-dev writes new payload to `localStorage` before verifying integrity; power loss mid-write corrupts both old/new.  
**Evidence:** File exists in payload; no checksum/atomic-write pattern visible in static scan.  
**Reproduction:** Throttle CPU → trigger self-update → kill process during `localStorage.setItem` → relaunch → observe corrupted payload.  
**Fix:** Write to `localStorage.seven_payload_staging` + SHA-256 → verify → atomic swap keys.  
**Regression:** Chaos test: inject `setItem` failure at random byte → verify rollback to previous valid payload.

### B08-006 — LOW — STRONG
**Surface:** `workspaces/seven-shell-final.js` (hash `9098a251…`) — race between `localStorage` sync tabs  
**Symptom:** Multi-tab (split-view) writes same keys without `storage` event coordination → last-write-wins loses concurrent edits.  
**Evidence:** Shell final manages workspace tabs; 85 `localStorage` refs imply shared keys. No `window.addEventListener('storage')` in grep.  
**Reproduction:** Open two tabs → edit different fields → close tab A → tab B overwrites A’s changes.  
**Fix:** Add `storage` listener; merge on conflict (per-field timestamps).  
**Regression:** Playwright multi-context test: two pages → concurrent edits → assert merge preserves both.

## Cross-System Contradictions / Races
1. **Android WebView vs. Chrome `localStorage` quota** — WebView may enforce lower quota; no adaptive chunking in bridge.
2. **Self-dev payload + workspace state share `localStorage` namespace** — no namespacing (`seven_payload_*` vs `seven_ws_*`) → key collision risk.
3. **Visual certification (`capture-android-release-profile.cjs`) wipes `/data/local/tmp/seven-visual`** — if app writes crash logs there, they’re lost before pull.

## Missing / Error States
- No `localStorage` corruption detection (CRC/checksum) on boot.
- No “storage full” user-visible toast; fails silently.
- No export/import backup UI (JSON dump of all `seven_*` keys).
- `sessionStorage` entirely absent — no tab-discard resilience.

## False Positives Rejected
- `index.html` 17 `.innerHTML=` — all appear to be trusted template interpolation, not user-controlled.
- 30 “API-key” terms — static strings in UI labels, not secrets.
- `MutationObserver` (7) — used for layout sync, not storage.

## Top 5 Highest-Priority Bugs
1. **B08-001** — Session refresh loses in-flight turn (user-visible, high frequency)
2. **B08-002** — Quota crash → silent history truncation (data loss)
3. **B08-003** — Upgrade path untested (blocker for OTA releases)
4. **B08-004** — Blob URL leak across sessions (memory pressure on low-end)
5. **B08-005** — Self-update atomicity (brick risk on power loss)
