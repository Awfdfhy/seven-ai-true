# Seven AI — Priority Systems Hyper-Polish Protocol

> Status: SPECIAL CAMPAIGN PROTOCOL
> Scope: Capability 16 Search / Retrieval Tools, 17 Knowledge / Files, 18 Vision, 19 RPG Engine, 20 Real Works / Canon Simulation Engine, 21 Titles / World Linguistic Engine only.
> Parent protocol: `SEVEN_ULTIMATE_POLISH_PROTOCOL.md` v2.1.
> Goal: keep these six systems in an intentionally reopened architecture state and repeatedly attack, expand, simplify, verify and re-derive them until additional material improvement can no longer be demonstrated.

---

# 0. Why this special campaign exists

Capabilities 16–21 are priority systems for Seven. They form a coupled chain:

`Discovery -> Source -> Perception -> World Simulation -> Canon Governance -> World Language`

A weakness in one poisons the others:
- weak retrieval creates weak evidence,
- weak source/version handling corrupts grounding,
- weak perception creates false observations,
- weak world-state handling creates narrative drift,
- weak canon governance creates fake fidelity,
- weak linguistic generation breaks world identity even when state is correct.

The ordinary Ultimate Polish protocol remains binding, but it is not sufficient as the stopping rule for this priority cluster. The six systems therefore receive a deeper repeated campaign rather than one A/B freeze cycle.

The previous #16–#21 Freeze Records are retained as **Baseline Freeze V1**. They are not deleted or rewritten into false completion claims. This protocol explicitly reopens them for stronger candidates.

---

# 1. Prime directive

> Do not move to Capability 22 while this special campaign is active unless the user explicitly ends it.

The campaign does not end because the architecture is large, elegant, novel, or difficult to improve casually.

It ends only when the **Saturation Gate** passes.

---

# 2. Hyper-Polish operating model

The campaign runs in **Rounds**. A round is not a rewrite pass. Each round must produce a testable architectural delta or record that no such delta survived evaluation.

Each round contains nine mandatory laboratories:

1. **Frontier Reconnaissance Lab**
2. **Ground-Truth & Assumption Lab**
3. **Architecture Expansion Lab**
4. **Hostile Destruction Lab**
5. **Scenario Gauntlet Lab**
6. **Cross-System Co-Evolution Lab**
7. **Mobile & Minimality Lab**
8. **Implementation Feasibility Lab**
9. **Proof / Reconciliation Lab**

The order may loop internally, but no round may skip a laboratory merely because a previous round covered it.

---

# 3. Round lifecycle

`Baseline -> Recon -> Reconstruct -> Expand -> Destroy -> Gauntlet -> Co-Evolve -> Compress -> Feasibility -> Proof -> Candidate`

Then:

`Candidate -> Independent Challenger Round`

A round may result in:
- `MATERIAL_IMPROVEMENT`
- `LOCAL_IMPROVEMENT`
- `SIMPLIFICATION_WIN`
- `REGRESSION_REJECTED`
- `NO_MATERIAL_IMPROVEMENT`

A claimed improvement without evidence is not an improvement.

---

# 4. Laboratory A — Frontier Reconnaissance

For every round, search beyond Seven's existing design.

Required source classes where relevant:
- current papers and benchmarks,
- production engineering write-ups,
- open-source systems,
- game-engine/world-simulation architecture,
- information retrieval/RAG systems,
- database/versioning/indexing systems,
- multimodal/OCR/document-understanding systems,
- GUI grounding and perception systems,
- interactive narrative and long-horizon consistency work,
- computational linguistics, morphology and localization systems,
- mobile/Android performance architecture.

Do not search only for systems that resemble Seven. Search adjacent fields for stronger primitives.

For every imported idea, record:
- problem solved,
- source field,
- why Seven needs it,
- what Seven already has,
- adaptation required,
- mobile/resource impact,
- new failure modes,
- accept/reject reason.

Fashion is not evidence.

---

# 5. Laboratory B — Ground Truth & Assumption Destruction

For each capability, rebuild the list of:
- authoritative state,
- derived state,
- ephemeral state,
- cache/index state,
- model-generated state,
- user-owned state,
- externally sourced state,
- irreversible/branching state,
- reconstructable state.

Then enumerate hidden assumptions and attempt to falsify them.

Examples:
- retrieval: semantic similarity implies evidential relevance,
- knowledge: extracted text is faithful to source layout,
- vision: coordinates remain valid after UI movement,
- RPG: fluent narration implies state consistency,
- canon: one timeline or one scalar fidelity measure is sufficient,
- titles: stylistic similarity implies linguistic authenticity.

No assumption survives merely because implementation already depends on it.

---

# 6. Laboratory C — Architecture Expansion

Temporarily maximize capability ceiling without worrying about final size.

For each system ask:
- what would the strongest useful version do?
- what additional state would make errors detectable rather than invisible?
- what additional evidence would make verification stronger?
- what additional representations would improve long-horizon reasoning?
- what would expert users want that the current architecture cannot express?
- what future models/providers/tools would expose missing abstractions?

This is the deliberate overbuild phase.

Nothing added here is guaranteed to survive.

# 8. Laboratory E — Scenario Gauntlets

These six systems must be tested through scenarios, not only component checklists.

## 8.1 Retrieval Gauntlets
At minimum:
- exact rare fact hidden in large corpus,
- paraphrased fact with misleading high-similarity distractors,
- time-sensitive/freshness conflict,
- contradictory sources,
- duplicated syndication,
- Arabic/English mixed retrieval,
- long-tail entity ambiguity,
- source says nothing relevant,
- adversarial SEO-style text,
- high-recall vs high-precision tasks,
- quote/citation-required tasks,
- offline/local-only degraded path.

Required measures include where applicable:
- recall/precision,
- nugget/claim coverage,
- source diversity/dependency,
- evidence precision,
- citation correctness,
- latency,
- bytes/network calls,
- RAM/CPU/battery cost.

## 8.2 Knowledge / Files Gauntlets
At minimum:
- versioned document updates,
- moved/renamed files,
- PDF with tables/figures,
- OCR-heavy scans,
- huge documents,
- duplicate documents,
- changed chunking/index versions,
- stale summaries/embeddings,
- conflicting project documents,
- deletion/purge/rebuild,
- mixed Arabic/English documents,
- source-range reconstruction.

## 8.3 Vision Gauntlets
At minimum:
- tiny text,
- dense document layout,
- charts/tables,
- screenshots with repeated controls,
- UI after layout shift,
- partial occlusion,
- zoom/scale/orientation changes,
- low contrast,
- Arabic/RTL interfaces,
- image + text disagreement,
- uncertain OCR,
- repeated visual elements,
- stale screenshot grounding.

Vision must be evaluated separately for:
- detection,
- OCR,
- layout,
- grounding,
- semantic interpretation,
- uncertainty calibration.

Action success is never counted as vision truth unless the action/effect layer separately verifies it.

## 8.4 RPG Gauntlets
At minimum:
- 20/50/100/250-turn sessions,
- inventory persistence,
- spatial consistency,
- relationship change,
- delayed consequence,
- simultaneous NPC goals,
- false player claim,
- player contradiction,
- branching and branch re-entry,
- retry/replay,
- save/load,
- deterministic seed replay,
- NPC knowledge isolation,
- hidden information,
- death/removal/irreversible world changes where the fictional scenario requires it,
- resource/state conservation,
- world-rule violations,
- adversarial attempts to force narrator inconsistency.

Fluency and entertainment are measured separately from state correctness.

## 8.5 Real Works / Canon Gauntlets
At minimum:
- exact canon trajectory without intervention,
- harmless insertion,
- elastic event perturbation,
- protected-anchor threat,
- irreversible divergence,
- multiple continuities,
- adaptation-vs-source conflict,
- incomplete source coverage,
- ambiguous canon,
- retcon/revised canon,
- future-knowledge leakage,
- character knowledge horizon,
- player action that invalidates a later event,
- branch propagation across many future events,
- canon re-entry when logically possible,

Required explicit outcomes:
- `CANON_COMPATIBLE`
- `CANON_GAP`
- `CANON_CONFLICT`
- `BRANCH_REQUIRED`
- `BRANCH_ACTIVE`
- `REENTRY_POSSIBLE`
- `REENTRY_BLOCKED`

No global scalar may replace the structural reason for these outcomes.

# 9. Laboratory F — Cross-System Co-Evolution

This is mandatory and is the major difference from ordinary per-capability polish.

The six systems are tested as one chain while preserving ownership boundaries.

Canonical ownership:
- Retrieval discovers candidates.
- Knowledge owns source/version identity and reconstructable source material.
- Vision owns source-bound observations from pixels/pages/screens.
- RPG owns session/world state and causal simulation.
- Real Works owns canon constraints, continuity and source-bound canon interpretation.
- Titles owns naming grammar and linguistic identity.

No subsystem may silently absorb another subsystem's authority.

## Cross-system mega-scenarios

### Scenario A — Source to Canon
`Search -> Fetch -> SourceVersion -> EvidenceUnit -> Canon Claim -> Scene Constraint`

Attack every handoff for loss of lineage or authority inflation.

### Scenario B — Visual Canon Source
`PDF/Image -> Vision/OCR/Layout -> Knowledge Source Range -> Canon Claim`

OCR uncertainty must survive into downstream canon confidence/coverage instead of disappearing.

### Scenario C — Long Interactive Canon
`Canon Pack -> RPG Session -> Player Action -> WorldDiff -> Canon Constraint Evaluation -> Branch/Re-entry -> Title Generation`

Run for long horizons and test future-anchor consequences.

### Scenario D — Mixed-Language Canon
Arabic user + English/Japanese-origin source metadata + localized titles + RTL UI.

Test entity identity, transliteration, localization provenance and retrieval stability.

### Scenario E — Missing Evidence
A scene requires a canon fact that retrieval cannot prove.

Correct behavior is `CANON_GAP`/targeted research, not invented completion.

### Scenario F — Source Revision
A SourceVersion changes after an earlier session or canon pack was compiled.

Test invalidation, stale derived objects, branch truth, revalidation and user-visible diagnostics.

# 10. Laboratory G — Mobile & Minimality

After maximizing the architecture, attack its existence cost.

For every primitive ask:
- can it be lazy?
- can it be reconstructed?
- can it live only in active projects/sessions?
- can it be represented compactly?
- can exact/lexical/deterministic logic handle the common path?
- is a model actually required?
- is an embedding actually required?
- does this need background work?
- can heavy indexes unload?
- can large artifacts stay off the hot path?

Required tiers:
- Lite
- Balanced
- Full

The Lite tier must remain genuinely useful, not merely Full with features silently broken.

No capability may impose global startup cost merely by existing.

---

# 11. Laboratory H — Implementation Feasibility

Architecture that cannot be implemented reliably on Seven's actual platform is not the strongest practical architecture.

For every proposed primitive record:
- implementation difficulty,
- required dependency,
- browser/Android compatibility,
- storage model,
- migration path,
- testability,
- fallback path,
- approximate runtime/resource class,
- whether it can be built incrementally,
- whether it creates permanent provider lock-in.

A feature may be deferred without being deleted from architecture, but dependency chains must be explicit.

# 13. Special evaluation doctrine

These systems are not judged by a single quality score.

Use a multi-axis vector including where applicable:
- factual/evidential correctness,
- source fidelity,
- long-horizon consistency,
- causal correctness,
- canon preservation,
- branch correctness,
- uncertainty honesty,
- linguistic authenticity,
- retrieval quality,
- perception grounding,
- recovery/replay,
- latency,
- RAM,
- CPU,
- battery/thermal,
- network,
- storage,
- UX clarity.

Critical correctness failures cannot be averaged away by high style/fluency scores.

Long-context and noisy-label evaluation must be represented because modern grounded-evaluation research shows these remain weak points in current systems.

---

# 14. Independent evaluators

A producer component may not be the sole evaluator of its own output.

Preferred hierarchy:
1. deterministic invariant/contract checks,
2. source/evidence checks,
3. replay/state-diff checks,
4. fixed benchmark gold/structured annotations,
5. independent qualified model judge only for properties that genuinely require judgment,
6. human review for unresolved benchmark/spec ambiguity when building gold sets.

Model judges may abstain and must not overwrite deterministic failures.

---

# 15. Long-horizon doctrine

Capabilities 19 and 20 must explicitly optimize survival over long interaction, not just turn quality.

At checkpoints test:
- established fact survival,
- invariant survival,
- ordering commitments,
- achievement commitments,
- character knowledge boundaries,
- causal consequences,
- branch identity,
- unreachable-future-event detection,
- replay consistency.

A beautiful 100th turn that contradicts turn 7 is a failure.

---

# 16. Canon Fidelity Ladder

Real Works should report structurally useful states instead of pretending universal certainty.

Suggested ladder:
- `SOURCE_LOCKED`: directly supported by identified source version/evidence.
- `SUPPORTED_INFERENCE`: derived with explicit reasoning/evidence chain.
- `CANON_GAP`: required information is not established.
- `CANON_CONFLICT`: sources/continuities conflict.
- `BRANCH_COMPATIBLE`: player divergence exists but local constraints remain consistent.
- `BRANCH_DIVERGED`: original future trajectory is structurally invalidated.

These are not scalar scores and do not replace claim-level epistemic verdicts.

# 17. World Simulation correctness model

RPG correctness must separate:
- physical/world facts,
- entity state,
- locations,
- inventory/ownership,
- relationships,
- goals/intentions,
- character knowledge,
- world rules,
- unresolved events,
- causal dependencies,
- narrative commitments,
- presentation prose.

The prose may be regenerated. Committed world state must not be silently rewritten to fit new prose.

---

# 18. Linguistic identity doctrine

World Linguistic Engine must never become a hidden copyrighted-text regurgitation layer.

It learns/represents abstract naming grammar and world linguistic constraints, then generates new names/titles under those constraints.

Official titles remain source-bound records rather than generated approximations.

Generated outputs should preserve provenance class:
- OFFICIAL
- OFFICIAL_LOCALIZED
- USER_DEFINED
- SEVEN_GENERATED
- IN_WORLD_GENERATED
- PLACEHOLDER

# 20. Anti-overengineering tribunal

At the end of every round, nominate at least three primitives for deletion or merger.

For each ask:
- does it solve a failure demonstrated by a gauntlet?
- can another primitive already express it?
- does it increase authority ambiguity?
- does it require always-on compute/storage?
- does it create a new sync/version problem?
- does it improve measured results?

If the answer is weak, remove it.

The strongest system is allowed to become smaller.

---

# 21. Frontier challenger rule

After a candidate appears stable, run a challenger using one deliberately different architectural philosophy.

Examples:
- graph-heavy vs ledger-heavy,
- schema-fixed vs open-schema,
- retrieval-first vs state-first,
- deterministic-first vs model-assisted,
- local-first vs remote-first,
- canonical trajectory vs commitment-only canon modeling.

The challenger does not need to win globally. It exists to expose blind spots.

---

# 22. Saturation Gate

This special campaign may end only when all conditions hold:

1. Two consecutive independent Hyper-Polish rounds produce `NO_MATERIAL_IMPROVEMENT` for the cluster or only local changes below acceptance threshold.
2. No unresolved Critical or High architectural failure remains in the current gauntlet suite.
3. Long-horizon RPG/Canon tests show no known architectural class of contradiction that lacks an explicit handling strategy.
4. Retrieval/Knowledge/Vision provenance survives cross-system handoffs without silent authority inflation.
5. `CANON_GAP`, conflicts and branches remain explicit under incomplete/adversarial evidence.
6. Titles preserve provenance, localization and grammar boundaries without becoming a canon authority source.
7. Mobile Lite path remains useful and within defined resource budgets.
8. A radically different challenger architecture fails to provide a material Pareto improvement.
9. Anti-overengineering tribunal finds no removable major layer with better cost/benefit.
10. Implementation feasibility review finds no architectural dependency that is fundamentally incompatible with Seven's intended Android/browser environment.

If any condition fails, the campaign continues.

# 25. First-round mandate

Round 01 must not simply restate existing #16–#21 designs.

It must specifically seek:
- missing evaluation dimensions,
- long-horizon failure classes,
- source/evidence leakage across system boundaries,
- stronger branch/re-entry semantics,
- stronger character/world knowledge isolation,
- open-schema vs fixed-schema tradeoffs,
- evidence-grounded verification before narrative output where justified,
- multimodal source uncertainty propagation,
- multilingual/Arabic stress cases,
- mobile resource cliffs,
- primitives that can be deleted.

The target is not cosmetic refinement.

The target is a stronger scientific architecture process capable of disproving Seven's own favorite designs.

# Final law

> These six systems are not finished when we run out of ideas. They are finished when repeated independent attempts to improve them stop producing a demonstrable material Pareto improvement under truth, canon fidelity, long-horizon consistency, mobile cost, recoverability and user experience constraints.
