# Seven Visual Implementation Waves 1.0

Status: EXECUTION_PLAN
Architecture: Visual Intelligence V1.4 frozen 2/2

## Principle
Implement evidence machinery and canonical primitives before rewriting every screen. Each wave is a coherent Mega-Campaign with one final integrated verification rather than dozens of tiny disconnected edits.

## Wave 1 - Visual Evidence Runtime
Build the machinery required to judge later visual candidates.

Deliver:
- expanded scenario capture manifest
- render-environment fingerprint
- structural geometry collector
- effective touch-target audit
- expanded contrast/state audit
- screenshot evidence manifest
- baseline registry
- visual diff classification structure
- privacy-safe synthetic fixtures
- regression-cemetery runner hooks

Do not claim multimodal Visual Judge runtime until it is actually connected.

## Wave 2 - Canonical Design Genome Runtime
Introduce one semantic token layer without a destructive one-shot rewrite.

Deliver:
- canonical theme/brand/Aurora/domain token schema
- typography/spacing/shape/motion token schema
- legacy --seven-* and --sb-* compatibility adapters
- Design Lint seed
- Genome Coverage Ledger
- incremental component migration path

Protected source remains untouched unless separately authorized.

## Wave 3 - Logo & Identity Tournament
Generate, inspect and compare logo families from the tournament brief.

Deliver:
- candidate asset manifest
- monochrome silhouettes
- tiny-size contact sheets
- adaptive-mask previews
- Day/Night treatments
- themed-icon previews
- distinctiveness review
- finalist evidence packets

No Android production asset replacement until a winner is approved and export verification passes.

## Wave 4 - Global Shell Tournament
Apply the winning/leading Genome candidates to:
- launch/onboarding
- sidebar/drawer
- top bar
- chat reading field
- message grammar
- composer
- status/Aurora
- dialogs
- settings
- permissions
- errors/offline/recovery

Run matched candidate portfolio rather than one redesign.

## Wave 5 - Domain Workspaces
Bring each domain into the same family while preserving its role:
- Core
- Build/Coding
- Research
- World/RPG
- Projects/Files/Tools

Verify interaction vocabulary and state semantics remain common.

## Wave 6 - Generated UI + Data Visualization
Implement typed component catalog, presentation firewall, safe fallback and governed chart/data-viz primitives.

## Wave 7 - Motion Genome
Implement and capture:
- launch
- navigation/workspaces
- streaming/message reveal
- thinking/research
- tool execution
- Deep Think
- success/warning/error
- theme shift
- RPG/World moments

Verify normal, repeated-use, interrupted, Lite, Reduced Motion and hidden routes.

## Wave 8 - Accessibility + Arabic/RTL Offensive
Attack:
- effective 48dp targets
- focus/semantics
- large text
- font fallback
- Arabic shaping
- mixed bidi
- text expansion
- keyboard/IME
- color distinctions
- TalkBack/device paths
- high-contrast/system personalization where available

## Wave 9 - Mobile Performance Offensive
Measure and optimize:
- startup visual work
- CSS/DOM/asset growth
- long tasks
- important animation frame throughput
- input responsiveness
- hidden work
- Lite/Balanced/Full behavior
- memory/battery/thermal evidence where device tooling supports it

Visual richness that cannot justify its cost is simplified.

## Wave 10 - Android Identity & Device Certification
Implement/prove:
- adaptive foreground/background
- monochrome/themed icon
- launcher masks
- splash identity
- edge-to-edge/insets
- system bars
- cutouts
- IME
- orientation/resizing
- representative Android device tiers

## Wave 11 - Visual Red Team
Attack:
- misleading semantic states
- stale goldens
- design drift
- generated UI escape
- raw token escape
- private screenshot leakage
- logo export mismatch
- Arabic/RTL edge cases
- one-handed reachability
- repeated motion fatigue
- low-resource degradation

## Wave 12 - Final Design Saturation & Freeze
Under a fixed implemented Design Genome and evidence environment:
- run independent Challenger A
- if MATERIAL, repair and reset
- run consecutive no-material rounds to 2/2
- freeze approved visual baseline and asset identities
- move to device/release proof rather than endless aesthetic tweaking

## Parallelism rule
Some waves can prepare evidence/assets in parallel, but promotion dependencies remain:
Visual Evidence Runtime -> Genome Runtime -> candidate tournaments -> integrated surfaces -> device certification -> final freeze.

## Completion definition
The visual program is complete only when:
- approved assets are the assets the build actually consumes,
- product surfaces use canonical genome coverage or documented escapes,
- required visual/structural/accessibility/performance gates pass,
- Android identity is device-proven,
- final implemented design reaches bounded saturation 2/2.

Architecture saturation alone is not visual completion.
