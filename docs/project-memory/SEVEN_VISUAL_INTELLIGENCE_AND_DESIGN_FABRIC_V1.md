# Seven Visual Intelligence & Design Fabric 1.0

Status: ARCHITECTURE_CANDIDATE
Governance: Seven Polishing V5.40 + Benchmark & Visual Evidence Fabric + Motion Evidence & Expert Judgment
Scope: the complete visible product system of Seven, including app shell, workspaces, chat, coding, research, RPG/World, settings, projects, tools, files, onboarding, errors, permissions, logo, launcher icon, splash mark, typography, iconography, themes, Aurora, motion and visual release evidence.

## Mission
Build a distinctive Seven design language that is beautiful, recognizable, fast, accessible, Arabic/RTL-native, Android-native where useful, and light enough for constrained phones.

The system must not optimize for screenshots alone. It must optimize the complete user experience across interaction, motion, information hierarchy, accessibility, state truth, device performance and brand identity.

## Prime laws
1. Beauty cannot override truth, accessibility, usability, performance or user agency.
2. A screenshot is evidence of pixels, not proof of semantics, interaction correctness, frame pacing or accessibility-tree correctness.
3. Subjective preference remains subjective. It can guide promotion only through explicit rubrics, independent judgment and uncertainty-aware comparison.
4. Seven may learn from platform systems and leading products but must not collapse into imitation. Platform convention is a constraint and reference, not Seven's identity.
5. Every major visual candidate competes against the exact locked baseline under matched scenarios.
6. Visual improvement is multi-axis. A candidate that improves elegance while materially worsening RTL, accessibility or mobile performance is not a winner.
7. Day and Night are two expressions of one identity, not two unrelated themes.
8. Aurora communicates authoritative runtime state only. Visual energy never creates authority.
9. Motion must have purpose, interruption behavior and a Reduced Motion equivalent.
10. The final visual architecture must remain lightweight. Decorative richness that materially increases startup, RAM, battery, storage or jank loses unless its value is proven and an acceptable lower tier exists.
11. Missing visual observations are not evidence that a defect does not exist.
12. A material requirement, evaluator, rendering environment or benchmark change starts a new comparison epoch.
13. Saturation is bounded to the tested design/evidence envelope. It does not mean universally perfect design.

# 1. Design Genome

The Design Genome is Seven's persistent visual grammar. New surfaces inherit it rather than inventing one-off styling.

## Genome axes
- color roles and tonal relationships
- Day/Night transformation rules
- Aurora semantic-state composition
- shape grammar and corner hierarchy
- spacing rhythm and density tiers
- typography hierarchy and Arabic/Latin pairing behavior
- icon geometry and stroke/fill conventions
- surface depth and border/shadow discipline
- focus/selection/hover/pressed/disabled language
- message/evidence/tool/result visual grammar
- motion timing, easing and choreography families
- responsive/adaptive layout grammar
- data visualization grammar
- error/warning/success/uncertainty grammar
- empty/loading/offline/cancelled states
- sound/haptic hooks where later supported, with visual equivalence

## Genome rule
A screen may have a domain personality without becoming a separate product.

Core = calm, clear, conversational.
Build = precise, technical, execution-oriented.
Research = evidence-dense, source-oriented, investigative.
World/RPG = immersive, narrative, atmospheric.

All four retain the same typography logic, spacing rhythm, interaction vocabulary, accessibility rules, icon family, Day/Night DNA and Aurora semantics.

# 2. Visual Intelligence Plane

## Inputs
- screenshots
- screen recordings
- frame sequences
- DOM/layout bounds
- accessibility/semantic tree where available
- CSS/design tokens
- interaction traces
- device/window/font/locale/theme metadata
- runtime frame timing and resource traces
- approved baseline artifacts

## Visual observations
The plane may detect or hypothesize:
- clipping, overlap and truncation
- weak hierarchy or excessive hierarchy
- inconsistent alignment and spacing
- density/crowding problems
- poor text measure and readability
- ambiguous controls
- visual-state ambiguity
- theme inconsistency
- icon/label mismatch
- RTL and mixed-bidi defects
- weak affordances
- layout imbalance
- excessive decoration
- brand drift
- state discontinuity across frames
- animation pacing/choreography defects
- apparent but unproven jank
- visual regression

Model-only observations remain derived until corroborated where objective proof is possible.

# 3. Structural Verification Plane

Objective visual claims should prefer deterministic evidence when available.

Checks include:
- contrast calculation from actual rendered/style values
- touch-target dimensions
- focus visibility and order where structurally observable
- semantic labels/roles
- overflow/clipping bounds
- text expansion
- font scaling
- minimum interactive spacing
- safe-area/inset behavior
- orientation/window resizing
- keyboard/IME obstruction
- Android adaptive-icon geometry
- Day/Night token parity
- Reduced Motion behavior
- asset size and decoding cost
- CSS/layout complexity budgets

Visual and structural channels may disagree. Preserve that conflict until resolved.

# 4. Candidate Studio

For every material visual problem, do not jump directly to one answer.

Candidate classes:
- simplify/remove
- hierarchy change
- typography change
- spacing/density change
- shape change
- color/tone change
- iconography change
- composition/layout change
- interaction-pattern change
- motion-only change
- information-architecture change
- domain-personality change
- brand-expression change
- no-change control

Use a candidate portfolio rather than a single linear redesign. Prune dominated candidates early, but preserve stylistic diversity until evidence is sufficient.

# 5. Render Lab

Every candidate is rendered against a bounded high-information scenario matrix.

Required scenario families:
- Day / Night
- Arabic RTL / English LTR / mixed bidi
- small phone / representative phone / larger window where relevant
- normal font / large font
- Lite / Balanced / Full performance tier
- Reduced Motion on/off where motion exists
- empty / short / long / extreme content
- loading / thinking / tool-running / verified / uncertain / warning / error / offline / cancelled
- keyboard open/closed where input is material

Use risk-based and pairwise coverage before Cartesian explosion.

# 6. Logo & Brand Identity Lab

The logo is a system, not a single PNG.

Required outputs:
- master mark
- Day mark treatment
- Night mark treatment
- Android adaptive foreground/background layers
- monochrome/themed-icon layer
- splash/launch mark
- tiny-size mark
- favicon/web mark if needed
- wordmark/lockup if justified
- motion mark for launch/brand moments

Android launcher constraints are treated as hard implementation evidence, including 108x108 dp adaptive layers, the protected inner safe region and monochrome/themed-icon support.

Logo evaluation lenses:
- instant recognizability
- silhouette strength
- tiny-size survival
- distinctiveness
- relation to Seven meaning without over-literal complexity
- Day/Night parity
- monochrome survival
- mask robustness across circle/squircle/other launcher shapes
- visual balance
- memory/recall hypothesis
- motion potential
- asset simplicity and render cost

Do not freeze a logo because one render looks impressive. It must survive the entire identity matrix.

# 7. Typography System

Typography is treated as product infrastructure.

Requirements:
- Arabic-first quality, not translated-afterthought layout
- stable Arabic/Latin hierarchy
- mixed-bidi robustness
- dynamic text expansion
- readable line length
- appropriate line-height
- numerical/code/source typography where needed
- clear distinction between conversation, metadata, evidence, code, tool output and critical state
- font loading/storage cost included in promotion decisions

No font choice may be accepted only because it looks premium in Latin screenshots.

# 8. Color, Theme & Aurora Composition

Color uses semantic roles rather than scattered literal values.

Layers:
1. Base theme roles: surfaces, text, borders, controls and elevation.
2. Brand roles: persistent Seven identity.
3. Aurora semantic roles: runtime state expression.
4. Domain personality roles: Core/Build/Research/World accents within the genome.
5. Accessibility overrides/tier reductions where needed.

Rules:
- semantic meaning cannot rely on color alone
- Aurora meaning is invariant between Day/Night
- warning/error/uncertainty remain distinguishable under all themes
- dynamic/system color may be supported only if Seven identity and semantic safety remain intact

# 9. Motion Genome

Motion classes:
- M0 decorative
- M1 interaction feedback
- M2 navigation/hierarchy
- M3 progress/process
- M4 critical state

Every material motion defines:
- purpose
- start/end state
- duration/easing family
- interruption/cancellation behavior
- gesture coupling when applicable
- RTL direction rule
- Reduced Motion substitute
- Lite tier behavior
- offscreen/hidden suspension
- frame/resource budget

Motion candidates lose if they hide latency dishonestly, imply completion early, create repeated fatigue or materially increase jank/battery cost.

# 10. Visual Judgment Council

No single multimodal evaluator owns taste.

Required lenses for major decisions:
- Product Design
- Interaction Design
- Information Architecture
- Brand Identity
- Typography
- Motion Design
- Accessibility
- Arabic/RTL Localization
- Mobile Performance
- Android Platform Fit
- Simplifier
- Broad-Audience Comprehension
- Distinctiveness / anti-imitation

Each finding records evidence channel, severity, confidence, objective/conventional/subjective class, expected gain and regression risk.

For high-impact subjective decisions, require structurally different judgment routes where practical rather than several copies of the same evaluator.

# 11. Design Tournament

Major candidates enter a tournament with locked requirements and baseline.

Promotion order:
1. invariant gate
2. structural/accessibility gate
3. functional task gate
4. RTL/localization gate
5. performance/resource gate
6. visual regression gate
7. hierarchy/readability comparison
8. brand/distinctiveness judgment
9. motion judgment where relevant
10. simplifier attack
11. holdout scenarios
12. final Pareto verdict

Verdicts:
- PROMOTE
- REJECT
- TRADEOFF_REQUIRES_DECISION
- INCONCLUSIVE
- ENVIRONMENT_INVALID
- MEASUREMENT_INVALID

No universal beauty score may erase underlying dimensions.

# 12. Design Regression Cemetery

Every material reproduced visual failure becomes a durable regression case where feasible.

Examples:
- clipped Arabic labels
- bidi corruption
- invisible delete/control on touch devices
- Day/Night contrast regression
- tiny logo collapse
- adaptive-icon clipping
- keyboard covering composer
- error/warning states becoming visually similar
- reduced-motion path losing meaning
- theme transition flash
- scroll/animation jank on Lite tier
- stale screenshot golden masking a real improvement
- one workspace drifting outside the Design Genome

# 13. Anti-Overfitting & Distinctiveness

Visual quality can overfit reviewers and references.

Defenses:
- public/dev/shadow/holdout visual scenarios
- rotating reference categories
- blinded candidate order where possible
- evaluator identity/version tracking
- fresh device/window samples
- anti-imitation check
- no single-trend dependency
- explicit novelty penalty when novelty harms comprehension
- reference analysis by principles, never pixel copying

# 14. Performance Constitution

Visual polish is constrained by Seven's mobile-first resource law.

Measure where relevant:
- startup bytes and startup work
- CSS/DOM growth
- asset bytes
- decode cost
- layout/recalc cost
- long tasks
- input-to-visible-response latency
- frame pacing/jank
- memory pressure
- hidden/offscreen activity
- sustained battery/thermal cost on representative device tiers

A premium effect must have either negligible cost or a clear lower-cost fallback. Heavy global canvas/WebGL/particle systems are not the default design strategy.

# 15. Android Grounding

Seven uses current Android guidance as platform evidence, not as a requirement to visually clone Android apps.

Grounding includes:
- Material 3 / Material 3 Expressive interaction and component research where useful
- Android 16 visual/system integration awareness
- adaptive icons with foreground/background and monochrome layers
- minimum practical touch targets, using Android's 48dp recommendation for touch interfaces as a strong baseline
- edge/inset/system-bar compatibility
- accessibility testing across automated, structural and manual routes

# 17. Campaign Order

The visual campaign runs in this order:

Phase 0 - Ground Truth
Inventory current UI, logo/assets, tokens, screenshots, workspaces, states, Android constraints and known defects.

Phase 1 - Goal & Requirement Lock
Freeze visual goals, protected functionality, performance envelope, accessibility/RTL constraints and evaluation constitution.

Phase 2 - Design Genome
Create the stable DNA before polishing individual screens.

Phase 3 - Logo & Identity Tournament
Generate and test multiple logo/identity families across Day/Night, monochrome, adaptive masks and tiny sizes. Do not freeze prematurely.

Phase 4 - Global Shell
Navigation, top bar, sidebar/drawer, composer, chat, status surfaces, dialogs, permissions, settings, errors and loading.

Phase 5 - Domain Workspaces
Core, Build/Coding, Research, World/RPG, Projects/Files/Tools.

Phase 6 - Typography/Iconography/Illustration
Unify visual language and remove one-off assets.

Phase 7 - Motion Genome
Launch, navigation, streaming, thinking, tool execution, Deep Think, success/error, RPG/world transitions and media states.

Phase 8 - Accessibility + Arabic/RTL Attack
Large text, touch, contrast, focus, mixed bidi, text expansion, reduced motion and extreme content.

Phase 9 - Mobile Performance Attack
Lite/Balanced/Full tiers, low-memory/slow-device behavior, jank/resource budgets and hidden-work suppression.

Phase 10 - Visual Red Team
Adversarial screen states, stale golden checks, brand drift, misleading states, hierarchy failures and anti-imitation review.

Phase 11 - Independent Saturation Challenges
Two consecutive independent rounds must find NO MATERIAL IMPROVEMENT under the same fixed visual constitution. Any material improvement resets the count to 0/2.

Phase 12 - Freeze
Freeze the bounded Design Genome and approved baseline set, then move to implementation/device certification rather than endless visual polishing.

# 21. Truth boundary

This document defines the strongest current visual-development architecture candidate. It does not claim that Seven's current UI, logo or motion already satisfies it. It also does not claim universal aesthetic perfection. Objective claims require objective evidence; subjective quality remains bounded judgment.

The next action is not to redesign everything immediately. The next action is to run Phase 0 and Phase 1, create the exact visual ground truth and fixed evaluation constitution, then begin the Design Genome and Logo Tournament.
