# Seven General Improvement Engine 1.0 — Recursive Evidence-Governed Improvement Laboratory

Status: ARCHITECTURE CANDIDATE
Scope: general-purpose improvement engine. It may improve architecture, algorithms, workflows, prompts, policies, UX systems, test systems, research systems, debugging systems, performance strategies and the polishing process itself. It is not an authority source and cannot self-promote.

## Prime law
Improvement must be demonstrated, not named.

A candidate is promoted only when independent evidence demonstrates a material class-level improvement over the incumbent without forbidden regression. A version number, larger design, additional feature count, benchmark cherry-pick or disappearance of a symptom is never sufficient.

## Generality
The engine accepts an ImprovementTarget contract rather than a Polishing-only target:
- target identity/version/hash
- authoritative requirements and invariants
- optimization axes
- forbidden regressions
- evidence requirements
- resource envelope
- environment envelope
- reversibility/rollback contract
- criticality class
- unknown/uncertain regions

This permits the same engine to serve later as the core of Polishing, Self-Evolution, Debugging strategy improvement, performance optimization, UX refinement and architecture tournaments.

## 200% Materiality Rule
"200%" is a materiality class, not a fabricated universal scalar. A qualifying recursive evolution must be a demonstrated step-change, not an ordinary polish delta. Where a dimension has a valid ratio scale, a >=2x threshold may be precommitted for that dimension. Where it does not, promotion requires a precommitted categorical step-change or multi-axis Pareto improvement with no forbidden regression. The system must never invent a percentage for aesthetics, correctness, safety or other non-ratio qualities.

Ordinary valuable improvements below this gate may be accumulated inside the current generation, but they do not consume one of the recursive-generation slots.

## Up-to-10 Recursive Generations
Maximum: 10 promoted recursive generations in one recursive campaign.
Minimum: 0.
There is no quota requiring ten promotions.

Generation n+1 uses the promoted engine from generation n to construct/challenge the next candidate, while immutable external governance remains outside the candidate's authority.

If no candidate satisfies the current generation gate: NO_QUALIFYING_EVOLUTION -> STOP.

## Escalating Hostility Ladder
Each promoted generation raises evaluation difficulty. Difficulty is a vector, never a cosmetic scalar:
- broader adversarial/counterexample families
- stronger hidden/holdout partitions
- harder distribution shifts
- longer-horizon scenarios
- more hostile interruption/recovery conditions
- tighter resource envelopes where relevant
- more diverse devices/locales/themes/accessibility states where relevant
- stronger contradiction search and negative evidence
- mutation/fault injection where safe
- stronger anti-overfit checks
- harder baseline competitors
- increased reproducibility demands

The ladder may only add difficulty that remains valid for the target contract. It cannot make a test irrelevant merely to claim greater harshness.

## Constitutional Separation
The candidate/Builder cannot:
- see hidden holdouts before evaluation
- rewrite the authoritative target contract
- weaken C0/C1 gates
- choose its final Judge
- modify Promotion Gate thresholds after seeing results
- delete unfavorable evidence
- grant itself permissions
- promote itself
- silently change benchmark identity

Builder, Challenger/Judge and Promotion Gate are logically separate roles. Independent/deterministic verification is preferred where feasible.

## Quality floor
Speed may remove redundant work, never required proof. V4.4 Velocity Fabric may schedule, cache, parallelize, prune and incrementally revalidate, but it cannot reduce the semantic quality gate.

## Anti-Goodhart / anti-self-deception
- no universal score
- preserve raw axis metrics and categorical verdicts
- hidden tests remain hidden from Builder
- rotate/adapt holdouts between promoted generations
- benchmark identity/version is locked per comparison
- detect suspicious metric gains with semantic regressions
- include negative controls and mutation tests where feasible
- evaluate the evaluator
- preserve failed candidates and reasons
- compare against incumbent and credible alternative baselines

## Plateau and saturation
A generation does not pass because effort was large. Stop when no qualifying evolution survives the current hostility gate. A separate bounded polishing saturation test may then use two independent consecutive no-material-improvement challenges.

## Resource discipline
Recursive improvement is an engineering/research workflow, not an always-on phone loop. Heavy recursive campaigns should run only when explicitly scheduled/authorized and should respect compute/network/battery/privacy budgets. The released Android app must not continuously burn resources attempting to redesign itself.

## Polishing mode
After this General Improvement Engine is stabilized, Seven Polishing becomes a governed specialization:
General Improvement Engine + V4.4 research/benchmark/visual/motion/expert/velocity laws + polishing-specific saturation/freeze semantics.
Thus polishing consumes the general engine rather than duplicating a second recursive optimizer.

## Self-Evolution integration
Seven Evolution Engine may use this engine to propose and evaluate improvements, but promotion authority remains external/governed. Evolution candidates cannot mutate their own evaluation constitution.

## Evidence states
IDEA -> RESEARCH_SUPPORTED -> ARCHITECTURE_ACCEPTED -> IMPLEMENTED -> TESTED -> DEVICE_VERIFIED -> RELEASE_PROVEN.
No recursive generation may infer a higher evidence state from a lower one.

## Truth boundary
Architecture acceptance proves only that this governance design is accepted. It does not prove that autonomous recursive improvement, benchmark generation, holdout management, evaluator independence or ten-generation evolution is implemented or effective in the Seven runtime.
