## Release Readiness + Saturation truth boundary
`release/release-readiness.cjs` now defines ten mandatory evidence domains: source integrity, regression suite, production dependencies, identity freeze, Android release visual, device accessibility, physical-device performance/resource, Seven Evals, final Red Team and rollback/recovery.

Evidence is typed as `CI`, `GOVERNED`, `INDEPENDENT_REVIEW`, `RELEASE_DEVICE` or `PHYSICAL_DEVICE`. Each receipt is bound to exact branch, commit, artifact SHA-256 and evidence SHA-256, plus source reference, producer/verifier contexts and freshness window. Independent-review evidence requires a different verifier context from the producer.

A release-readiness manifest can PASS only if all ten domains exist, are fresh, match the exact release identity and satisfy their evidence-class floor. Saturation `2/2` then requires two PASS rounds on the same release identity, round 2 later than round 1, and refreshed independent evidence **and** independent verifier contexts for Identity Freeze, Seven Evals and Final Red Team. Duplicating round 1 cannot manufacture saturation.

This is a gate, not fabricated evidence. Current missing physical-device/independent-review facts remain missing until real evidence is ingested.
