# Seven Visual Intelligence & Design Fabric 1.1 - Evidence and Usability Hardening

Status: ARCHITECTURE_CANDIDATE
Supersedes only where stricter: V1.0
Governance: Polishing V5.40 + Visual Evaluation Constitution VISUAL-EPOCH-1 until epoch is deliberately renewed

## 1. Behavioral Experience Plane

Visual design is evaluated as an interaction system, not a picture.

For material flows, capture where feasible:
- task completion success
- time to first correct action
- time to critical action
- wrong-action / mis-tap count
- backtracking
- discoverability failures
- comprehension questions for semantic states
- recovery from error
- navigation path length
- repeated-use friction

These observations are behavioral evidence, not aesthetic authority. They are compared under matched tasks and clearly labeled as simulated, expert-run or human/device evidence.

## 2. Judge Calibration & Disagreement Fabric

Every decisive visual judge records:
- evaluator identity/version
- lens
- calibration-set result
- confidence
- abstention support
- candidate-order/blinding state where applicable
- evidence references

### Disagreement rule
If independent qualified routes disagree materially:
1. preserve disagreement,
2. identify whether it is objective, conventional or subjective,
3. seek an orthogonal evidence route when useful,
4. return INCONCLUSIVE or TRADEOFF_REQUIRES_DECISION if disagreement remains.

Major subjective decisions cannot be promoted by averaging away a serious dissent on a protected concern.

## 3. Asset Provenance & Distinctiveness Firewall

Every imported/generated visual asset carries:
- asset hash
- generation/import origin
- source/reference lineage where available
- license/usage status for external assets
- transformation lineage
- intended role
- approved variants

### Anti-copy review
Before brand freeze:
- compare finalist silhouettes, geometry and overall impression against a bounded reference landscape of relevant major AI/software/app identities,
- flag suspicious similarity for human/design review,
- prefer principle-level inspiration over pixel/style copying,
- preserve evidence of references consulted.

This reduces imitation/collision risk but is not trademark clearance or a legal guarantee.

## 4. Render Environment Fingerprint

Every decisive rendered artifact binds:
- build/commit
- browser/WebView/runtime version
- capture code version/hash
- viewport
- DPR/density
- OS/runner/device class
- font family files/versions or resolved font fingerprint when available
- locale
- text scale
- direction
- theme
- Aurora state
- performance tier
- Reduced Motion state
- relevant color/display mode

A material environment change that can alter the verdict invalidates direct A/B comparison or starts a new epoch.

## 5. Visual Privacy & Data Minimization

Default visual evaluation uses synthetic or explicitly safe fixtures.

Rules:
- never capture credentials, API keys, private tokens or authentication surfaces into design datasets,
- do not use personal/project content when synthetic fixtures can test the same layout,
- redact or substitute sensitive values before capture,
- keep screenshots only as long as their evidence role requires,
- bind evidence to minimal required context,
- treat uploaded/private visual material according to its original access boundary,
- no visual evaluator may convert captured content into new action authority.

## 6. Accessibility Expansion

Release-level visual claims require broader evidence than contrast alone.

Add checks/evidence for:
- effective 48dp ordinary mobile touch targets
- semantic name/role/value
- focus order and focus visibility
- keyboard navigation where supported
- text/display scaling and reflow
- TalkBack/screen-reader behavior on device before device-certified release
- color-vision-deficiency resilience where color distinctions matter
- high-contrast/forced-color compatibility where applicable
- Reduced Motion semantic equivalence
- one-handed reachability review for primary mobile flows

Color-vision simulation is diagnostic evidence, not a substitute for contrast/semantic checks.

## 7. Android System Integration Plane

Device validation expands to:
- edge-to-edge rendering
- status/navigation/system-bar contrast
- safe insets
- gesture navigation exclusion/conflict checks where relevant
- display cutouts
- portrait/landscape
- resize/multi-window
- foldable/tablet diagnostics when material to supported layouts
- IME open/close/resizing
- adaptive/themed launcher icon behavior
- Android splash integration

Browser viewport evidence remains a lower tier than physical/emulated Android system evidence.

## 8. Candidate Studio Isolation

Visual candidates are created in an isolated candidate workspace.

During a comparison epoch the candidate may not modify:
- decisive evaluation constitution
- baseline registry
- holdout definitions
- judge configuration used to decide its own promotion
- protected source unless separately authorized
- regression-cemetery expected outcomes

Candidate artifacts bind to:
- baseline hash
- candidate hash
- evaluation constitution hash
- scenario-matrix hash
- Design Genome version
- render-environment fingerprint

A candidate that changes its own exam is rejected or evaluated in a new epoch.

## 9. Design Genome Migration Ledger

Canonical Design Genome adoption is incremental.

Every migration unit records:
- legacy token/component
- canonical replacement
- compatibility mapping
- affected surfaces
- screenshot/structural scenarios
- performance delta
- rollback mapping
- migration state

States:
- LEGACY
- MAPPED
- DUAL_READ
- CANONICAL
- LEGACY_RETIRED

No global search-and-replace migration is allowed without component/scenario proof.

## 10. Component State Completeness

Reusable components must define relevant states explicitly:
- default
- hover where meaningful
- focus
- pressed
- selected/active
- disabled
- loading/busy
- success
- warning
- error
- offline/unavailable where relevant

Missing states are design debt, not silently inherited browser behavior.

## 11. Reference Landscape Research

Visual research is evidence-driven and bounded.

For each major design/brand campaign:
- study platform conventions,
- study multiple product categories rather than one competitor,
- extract principles, not pixels,
- record contradictions and tradeoffs,
- include Arabic/RTL examples where available,
- include accessibility and mobile-performance evidence,
- stop when marginal design information is low.

References cannot become authority over Seven's product requirements.
