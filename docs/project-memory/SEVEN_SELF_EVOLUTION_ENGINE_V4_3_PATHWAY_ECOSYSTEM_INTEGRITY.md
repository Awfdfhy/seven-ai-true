# Seven Self-Evolution Engine 4.3 — Pathway & Ecosystem Integrity

Status: ARCHITECTURE_CANDIDATE
Parent: Self-Evolution Engine 4.2
Governance: V5.40 Meta-Assurance Closure

V4.3 closes material gaps in proving that retained experience and evolving artifacts improve Seven through the intended mechanism rather than through confounded final-score gains.

## 1. Experience Pathway Proof
When a promotion claim depends on retained experience, evidence distinguishes:
- SAVE: was the relevant experience captured correctly?
- REPRESENT: was it transformed into the intended reusable form?
- RETRIEVE: was the right record retrieved under the later task?
- APPLY: did the agent actually use it in the decision path?
- UPDATE: was outdated/incorrect experience revised when contradicted?
- OUTCOME: did the pathway improve the target result?

A better final score without pathway evidence supports only an outcome claim, not a claim that the experience mechanism itself improved.

## 2. Matched Persistence Controls
Where practical, experience-driven improvements are evaluated under matched conditions with retained experience enabled and disabled, or with the proposed pathway replaced by a simpler reference. This isolates whether persistence itself contributed.

## 3. Experience Supersession Graph
Experience records support explicit relations:
- SUPERSEDES;
- REFINES;
- CONTRADICTS;
- SPECIALIZES;
- INVALIDATED_BY_ENVIRONMENT;
- RETIRED.

Retrieval respects these relations so stale procedures do not remain co-equal with newer evidence merely because they are semantically similar.

## 4. Substrate Binding
Every claimed Self-Evolution improvement records the execution substrate on which it was demonstrated:
- model/provider/version;
- tool runtime;
- context/memory configuration;
- device/environment class;
- scaffold/harness version.

A gain demonstrated on one substrate does not automatically become a substrate-independent claim.

## 5. Fixed-Substrate Meta Evaluation
When evaluating an improved harness, planner, memory strategy, or development mechanism, hold the execution model/provider fixed where practical. Cross-substrate tests are additional transfer evidence rather than a replacement for mechanism attribution.

## 6. Transfer Matrix
Meta-Evolution records transfer across relevant substrate/target classes:
- same model, new tasks;
- new model, same tasks;
- new model, new tasks;
- different provider/tool environment;
- relevant mobile/device tier.

The promoted claim scope matches observed transfer. Partial transfer is recorded as partial rather than generalized.

## 7. Tool Creation Stages
A generated tool progresses through:
DRAFT_INTERFACE
→ INTERFACE_VALIDATED
→ FUNCTION_VALIDATED
→ COMPOSITION_VALIDATED
→ LIBRARY_ACCEPTED
→ PROMOTION_ELIGIBLE.

Downstream task success cannot skip basic interface or functional correctness evidence.

## 8. Tool Library Health
The evolving tool ecosystem is evaluated as a software artifact, not only as a list of individually passing tools.

Library checks include:
- duplicate/redundant capabilities;
- alias/name collisions;
- schema/interface consistency;
- composition success;
- dependency compatibility;
- regression stability;
- resource cost;
- permission compatibility;
- maintenance debt;
- deprecation/retirement path;
- whether a new tool should instead reuse or extend an existing capability.

## 9. Downstream Attribution
When a newly generated tool changes downstream performance, evidence records whether the gain came from interface quality, tool logic, planner selection, retrieval/discovery, execution model, or changed task budget where separable.

## 10. Artifact Ecosystem Regression Set
Failures involving tool interactions, stale procedures, retired artifacts, interface changes, or composition conflicts become ecosystem-level regression cases. Passing a tool's isolated unit tests does not erase system-level regression evidence.

## 11. Mechanism-Level Meta Promotion
A development-method improvement may be promoted as a general Self-Evolution mechanism only when evidence supports the mechanism itself across the claimed target/substrate envelope. Otherwise it remains a local strategy tied to the demonstrated campaign class.

## 12. Pathway Evidence in Promotion Bundle
PromotionBundle now includes, where relevant:
- pathway-evidence record;
- persistence-on/off or reference comparison;
- substrate identity;
- transfer matrix;
- experience supersession changes;
- tool-library health delta;
- ecosystem regression impact.

## Truth boundary
Architecture only. V4.3 does not claim pathway instrumentation, matched persistence experiments, substrate-transfer runners, or tool-library health runtime is implemented.
