## SEVEN MAXIMUM EFFORT — DISCOVERY COVERAGE AUDIT 01

Goal: determine whether Seven Tool Fabric discovery is approaching practical saturation, identify genuine capability gaps, and prevent both premature closure and tool-count bloat.

Audit all completed Wave 01–10 reports against:
- `SEVEN_CAPABILITIES_MAP.md`
- `SEVEN_TOOL_FABRIC_2_RESEARCH_PROTOCOL.md`
- `SEVEN_ULTIMATE_POLISH_PLAN.md`
- Android-first/runtime constraints
- the stated goal of maximum useful capability coverage with minimum duplication/overhead.

For each capability/domain classify:
- DEEP_COVERAGE
- PARTIAL_COVERAGE
- ARCHITECTURE_ONLY
- UNEXPLORED_HIGH_VALUE
- UNEXPLORED_LOW_VALUE
- OUT_OF_SCOPE_FOR_TOOL_DISCOVERY

Do not declare a domain covered merely because one library was mentioned. Do not create a new wave merely because a technology exists.

Specifically search for gaps in:
- memory/retrieval/context compilation
- model/provider routing, capability discovery, structured outputs, streaming and cancellation
- observability/resource/performance measurement
- recovery/migrations/import/export/backups
- data analysis/visualization
- mathematical/symbolic computation
- geospatial/maps/weather/public structured data
- document/media production/transformation
- collaboration/sync only where compatible with authority
- external productivity/connectors after generic authorization groundwork
- knowledge/reference utilities not already covered
- any capability category discovered during prior waves but left unresolved

For every proposed new wave answer:
1. What capability is missing?
2. Why existing Waves cannot already provide it?
3. What measurable user value could it add?
4. Does it belong on-device, lazy, host/remote, or adapter-only?
5. What is the duplication/bloat risk?
6. What would justify rejecting the entire wave?

Saturation rule:
Tool discovery may close only when all remaining uncovered domains are either low-value, product/provider-specific rather than architectural, deferred to a non-Tool Boss, or documented as explicit gaps.

Preserve the audit and next-wave queue in GitHub. Do not modify production code, delete files, or merge protected branches.
