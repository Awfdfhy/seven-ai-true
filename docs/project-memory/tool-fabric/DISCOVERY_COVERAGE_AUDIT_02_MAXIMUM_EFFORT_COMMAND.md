## SEVEN MAXIMUM EFFORT — TOOL FABRIC DISCOVERY COVERAGE AUDIT 02

Goal: determine whether broad Tool Fabric 2.0 discovery has reached practical saturation after Waves 01–18, without confusing “many researched tools” with actual capability coverage.

Canonical inputs:
- `SEVEN_CAPABILITIES_MAP.md`
- `SEVEN_MASTER_PLAN.md`
- `SEVEN_TOOL_FABRIC_2_RESEARCH_PROTOCOL.md`
- `DISCOVERY_COVERAGE_AUDIT_01.md`
- Waves 01–18 commands/reports/evidence
- current Tool Fabric Deep Polish directory/state

Audit method:
1. map every capability/tool domain to at least one architecture boundary and candidate/evidence set;
2. identify P0/P1 capability gaps not covered by existing waves;
3. distinguish tool-discovery gaps from Ultimate Polish architecture/product work;
4. detect duplicated candidates/contracts and opportunities to simplify;
5. identify categories that are useful but P2/deferred rather than reasons to keep broad discovery open;
6. assess Android/base-APK implications;
7. assess security/authority/lineage/verification coverage;
8. challenge the conclusion: search conceptually for missing high-value general-assistant capabilities;
9. close discovery only if additional broad searching has lower expected value than deep-polishing the selected stack.

Saturation rule:
- `SATURATED_FOR_BROAD_DISCOVERY` means no material unresearched P0/P1 capability class remains.
- It does not mean every provider/library is known or every component is implemented.
- New discoveries may still be admitted later through targeted research if a concrete need, failure or technological change appears.

Required output:
1. Waves 01–18 coverage matrix
2. remaining gaps by P0/P1/P2/out-of-scope
3. duplication/simplification findings
4. final discovery verdict
5. transition plan into tool-by-tool Deep Polish
6. ordered Deep Polish queue
7. conditions that would reopen broad discovery

Preserve the audit in GitHub. Do not modify production source, delete files or merge protected branches.
